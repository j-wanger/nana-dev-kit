1. End-to-End Flows

Install Flow
Trigger: git clone … && ~/nana-dev-kit/install.sh — run once per machine
  1. Validates source files exist (SKILL.md, nana-soul.md, memory_server/)
  2. Copies /py-init skill → ~/.claude/skills/py-init/SKILL.md
  3. Copies identity rule → ~/.claude/rules/nana-soul.md
  4. Writes kit path → ~/.claude/.nana-dev-kit-path
  5. Copies memory server → ~/.claude/memory_server/ (12 .py + requirements.txt)
  6. Creates isolated venv at ~/.claude/memory_server/.venv/ (graceful fallback if python3 -m venv unavailable)
  7. Pip-installs required deps: mcp, pydantic, pyyaml, nanoid, httpx
  8. Registers MCP server in ~/.claude/settings.json via idempotent JSON merge (handles: no file, existing without mcpServers, existing with mcpServers)
Scaffold Flow — New Project
Trigger: /py-init in an empty directory
  1. Reads kit path from ~/.claude/.nana-dev-kit-path
  2. Detects no existing project markers (pyproject.toml, setup.py, .pre-commit-config.yaml, etc.)
  3. Prompts for package name and description
  4. Copies all 5 layers from templates/:
    • AGENTS.md + GitHub instructions → Layer 1
    • .claude/rules/nana-soul.md + py-session-state.md → Layer 2
    • .claude/hooks/ (6 scripts) + settings.json → Layer 3
    • .pre-commit-config.yaml → Layer 4
    • .github/workflows/ci.yml + PR template + CODEOWNERS → Layer 5
  5. Substitutes placeholders: {{PACKAGE_NAME}}, {{PROJECT_DESCRIPTION}}, {{PROJECT_NAME}}
  6. Runs make sync-rules to propagate AGENTS.md → CLAUDE.md, Copilot, Cursor, Gemini
Scaffold Flow — Existing Project
Trigger: /py-init in a project with existing config
  1. Detects existing project markers
  2. Feasibility scan: 10-dimension assessment (build system, source layout, linter, type checker, test framework, pre-commit, deps, agent config, CI, secrets)
  3. Each dimension classified: compatible upgradeable blocking
  4. Presents scan report table — requires explicit approval to proceed
  5. Transform: upgrades toolchain in place (merge, not overwrite)
  6. Validation: verifies all layers are wired correctly post-transform
Development Flow
Trigger: opening Claude Code in a scaffolded project
  1. SessionStart hook fires → loads context from 4 sources (all optional, graceful skip):
    • .dev-wiki/_CURRENT_STATE.md — active phase + recommended action
    • .memory/MEMORY.md — project memory snapshot
    • PROJECT_STATE.md — manual cross-session notes
    • .claude/rules/py-session-state.md — compaction-safe session state
  2. During coding: hooks fire on tool use:
    • Every file write → auto-ruff-format + secret scan + audit log
    • Every bash command → dangerous command blocker
  3. On stop: test gate checks if pytest ran (blocks if Python files modified but no test run) + 6-point code review prompt
Lifecycle Flow
Trigger: /dev-init → /dev-plan → implement → /dev-debrief
  1. /dev-init — bootstraps .dev-wiki/ with phases, architecture, state, tasks
  2. /dev-plan — plans one phase at a time: loads state → asks questions → proposes approach → reviews → writes tasks
  3. Implement — follows task order with TDD cycle (RED → GREEN → REFACTOR → VERIFY). Success criteria verified per task. Blocked after 3 failed attempts.
  4. /dev-debrief — captures session work: decisions, journal, state refresh
Sync Flow
Trigger: make sync-rules after editing AGENTS.md
  1. Reads AGENTS.md (single source of truth)
  2. Writes 4 outputs with AUTO-GENERATED headers:
    • CLAUDE.md — Claude Code
    • .github/copilot-instructions.md — GitHub Copilot
    • .cursor/rules/main.mdc — Cursor
    • GEMINI.md — Gemini Code Assist
  3. Pre-checks: validates AGENTS.md exists, target directory is writable

3. Hook System Walkthrough

Claude Code hooks are configured in .claude/settings.json. Each hook fires at a specific lifecycle event and receives tool input as JSON on stdin.

EventMatcherScriptBehaviorExit Codes
SessionStart — session-start.sh Loads project context from 4 sources (dev-wiki, memory, project state, session state). All optional — missing files silently skipped. 0 = success (always)
PreToolUse Bash block-dangerous-bash.sh Blocks: rm -rf /|~|.., git push --force, --no-verify, git reset --hard. Pattern-matched via grep. 0 = allow, 2 = block (stderr shown to AI)
PostToolUse Write|Edit|MultiEdit auto-ruff-format.sh Auto-formats .py files with uv run ruff check --fix + ruff format. Silent on non-Python files. Requires uv. 0 = success (always, errors suppressed)
PostToolUse Write|Edit|MultiEdit scan-secrets.sh Scans written files via gitleaks (preferred) or fallback regex for API keys, tokens, passwords. Warns on stderr, does not block. 0 = success (always, warning only)
PostToolUse Write|Edit|MultiEdit audit-log.sh Appends JSONL record to .nana/audit.jsonl: timestamp, tool name, file path, model. Creates .nana/ if needed. 0 = success (always)
Stop — check-tests-were-run.sh If Python files were modified in session, checks if pytest was run. Blocks stop if not — forces test execution. 0 = allow stop, 2 = force continue
Stop — py-review-stop-prompt.md Prompt-type hook: 6-point review checklist (duplicates, missing imports, bare excepts, test coverage, API usage, hardcoded secrets). n/a (prompt, not script)

Hook Data Flow

  Claude Code invokes a tool (Write, Edit, Bash, etc.)
       │
       ├── PreToolUse hooks receive:  { "tool_name": "Bash", "input": { "command": "..." } }
       │     └── block-dangerous-bash.sh reads .input.command, pattern-matches
       │
       ├── Tool executes
       │
       └── PostToolUse hooks receive: { "tool_name": "Edit", "input": { "file_path": "..." } }
             ├── auto-ruff-format.sh reads .input.file_path, runs ruff if .py
             ├── scan-secrets.sh reads .input.file_path, scans content
             └── audit-log.sh reads .input.file_path + .tool_name, appends JSONL

5. Quality Signals

Error Handling

  • install.sh: upfront source validation (fail-fast before any copy), venv creation with graceful fallback (memory is optional), pip install failure warns but continues
  • sync-rules.sh: validates AGENTS.md exists (exit non-zero with stderr), validates target directory is writable before any writes
  • Hooks: all PostToolUse hooks exit 0 on error (non-blocking) — writes should never be blocked by hook failures. PreToolUse block-dangerous-bash uses exit 2 for intentional blocks only.
  • MCP registration: idempotent JSON merge handles 3 cases (no file, partial, complete) without data loss

Idempotency

  • install.sh: re-running produces identical results — file copies overwrite, venv reuses existing, JSON merge preserves other mcpServers entries
  • sync-rules.sh: re-running overwrites outputs with same content (deterministic from AGENTS.md)
  • MCP JSON merge: overwrites only the memory key — other MCP servers untouched
  • Venv bootstrap: skips venv creation if .venv/bin/python3 already exists, only runs pip install

Test Coverage

test_enforce.sh9 assertions, 137 lines
test_harden.sh0 assertions, 138 lines
test_install.sh33 assertions, 303 lines
test_sync_rules.sh15 assertions, 100 lines
test_templates.sh64 assertions, 445 lines

Total: 121 assertions across 5 test scripts. Run with make test.

Edge cases covered: missing source files, unwritable directories, MCP registration (no file / partial / complete), venv fallback, idempotency (diff between runs).

Safety Boundaries

  • PreToolUse gate: blocks rm -rf on /, ~, ..; blocks force-push; blocks --no-verify; blocks git reset --hard
  • Secret scanning: dual-layer — gitleaks (preferred) + regex fallback on every file write
  • Test gate: Stop hook blocks session completion if Python files modified but pytest not run
  • Pre-commit gitleaks: scans all staged files at commit time
  • CI secret scan: gitleaks-action as final barrier before merge

Graceful Degradation

  • Session-start hook: each of 4 sources independently optional — missing files silently skipped
  • auto-ruff-format: requires uv + ruff — silently no-ops if unavailable
  • scan-secrets: falls back from gitleaks to regex if gitleaks not installed
  • Venv bootstrap: warns and continues if python3 -m venv unavailable — memory is optional
  • Memory server fastembed: try/except guarded — embedding features degrade to text-only

Audit Trail

  • Every file write logged to .nana/audit.jsonl (timestamp, tool, path, model)
  • Dev-wiki journal captures session decisions and observations
  • Dev-wiki log tracks all planning and debrief events with timestamps
  • Git history preserves phase-attributed commits (one per phase)
