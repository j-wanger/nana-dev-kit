1. End-to-End Flows

Install Flow
Trigger: git clone … && ~/nana-dev-kit/install.sh [--all|--core-only|--no-python|--dry-run|--status]
  1. Validates source files exist. Parses module flags (default: --all)
  2. Core module: copies 3 identity rules (nana-soul.md, nana-personal.md, file-lifecycle.md) + kit path marker + memory_server/
  3. Python module: copies py-init + spec skills (skip with --no-python)
  4. Dev-wiki module: copies 6 dev-lifecycle skill dirs; enforcement/lifecycle hooks are project-scoped and install per-project (via /py-init or --project-local), not globally
  5. Knowledge-wiki module: copies 11 wiki skill dirs
  6. Creates isolated venv at ~/.claude/memory_server/.venv/, installs deps
  7. Registers MCP server + hook events in ~/.claude/settings.json via idempotent JSON merge
  8. Creates .claude/enforce marker for project opt-in
  9. Outputs “Getting Started” with 3 paths: /dev-init, /py-init, /wiki-init
Scaffold Flow — New Project
Trigger: /py-init in an empty directory
  1. Reads kit path from ~/.claude/.nana-dev-kit-path
  2. Detects no existing project markers (pyproject.toml, setup.py, .pre-commit-config.yaml, etc.)
  3. Prompts for package name and description
  4. Copies all 5 layers from templates/:
    • AGENTS.md + GitHub instructions → Layer 1
    • .claude/rules/nana-soul.md + py-session-state.md → Layer 2
    • .claude/hooks/ (6 scripts) + settings.json → Layer 3
    • .pre-commit-config.yaml → Layer 4
    • .github/workflows/ci.yml + PR template + CODEOWNERS → Layer 5
  5. Substitutes placeholders: {{PACKAGE_NAME}}, {{PROJECT_DESCRIPTION}}, {{PROJECT_NAME}}
  6. Runs make sync-rules to propagate AGENTS.md → CLAUDE.md, Copilot, Cursor, Gemini
Scaffold Flow — Existing Project
Trigger: /py-init in a project with existing config
  1. Detects existing project markers
  2. Feasibility scan: 10-dimension assessment (build system, source layout, linter, type checker, test framework, pre-commit, deps, agent config, CI, secrets)
  3. Each dimension classified: compatible upgradeable blocking
  4. Presents scan report table — requires explicit approval to proceed
  5. Transform: upgrades toolchain in place (merge, not overwrite)
  6. Validation: verifies all layers are wired correctly post-transform
Development Flow
Trigger: opening Claude Code in a scaffolded project
  1. SessionStart hook fires → loads context and runs checks:
    • .dev-wiki/_CURRENT_STATE.md — active phase + recommended action
    • .claude/rules/active-phase.md — gate compliance check
    • .claude/rules/py-session-state.md — compaction-safe session state
    • Memory search guidance from active task topic
    • Stale .pending-commit sidecar detection
    • Crash recovery (commit mtime vs state mtime)
    • Enforcement status + [nana:kit] summary line
  2. During coding: hooks fire on tool use:
    • Every file write → auto-ruff-format + secret scan + audit log + post-commit detection
    • Every bash command → dangerous command blocker + loop detection
    • Implementation writes → enforce-spec blocks without approved spec
  3. On stop: enforce-loop checks deliverables, test gate checks pytest, 6-point code review prompt
Lifecycle Flow
Trigger: /dev-init → /spec → /dev-plan → implement → /dev-debrief
  1. /dev-init — bootstraps .dev-wiki/ with phases, architecture, state, tasks
  2. /spec — structured contract with adversarial constraints and two-tier review (Tier 0 structural lint + Tier 1 semantic subagent). Provenance marker <!-- nana:approved -->
  3. /dev-plan — plans one phase: state loader → cross-wiki knowledge → T0 thinking → approach reviewer → plan reviewer → artifact writer
  4. Implement — follows task order with TDD cycle (RED → GREEN → REFACTOR → VERIFY). Success criteria verified per task. Blocked after 3 failed attempts.
  5. /dev-debrief — significance-scored capture: decisions, journal, memory harvest, review gate, state refresh
Sync Flow
Trigger: make sync-rules after editing AGENTS.md
  1. Reads AGENTS.md (single source of truth)
  2. Writes 4 outputs with AUTO-GENERATED headers:
    • CLAUDE.md — Claude Code
    • .github/copilot-instructions.md — GitHub Copilot
    • .cursor/rules/main.mdc — Cursor
    • GEMINI.md — Gemini Code Assist
  3. Pre-checks: validates AGENTS.md exists, target directory is writable

3. Hook System Walkthrough

Claude Code hooks are configured in .claude/settings.json. Each hook fires at a specific lifecycle event and receives tool input as JSON on stdin.

EventMatcherScriptBehaviorExit Codes
SessionStart — session-start.sh Loads context (dev-wiki state, gate check, session state), checks enforcement status, detects crash recovery, clears stale sidecars, emits [nana:kit] summary. 0 = success (always)
PreToolUse Bash block-dangerous-bash.sh Blocks: rm -rf /|~|.., git push --force, --no-verify, git reset --hard, chmod 777. Pattern-matched via jq + grep. 0 = allow, 2 = block
PreToolUse Write|Edit enforce-spec.sh Blocks implementation writes without approved spec. Checks provenance marker (<!-- nana:approved -->) or exit criteria. Path allowlist for meta/test/docs. Events logged. 0 = allow, 2 = block (global hook)
PostToolUse Write|Edit|MultiEdit auto-ruff-format.sh Auto-formats .py files with ruff check --fix + ruff format. Silent on non-Python files. 0 = success (always)
PostToolUse Write|Edit|MultiEdit scan-secrets.sh Scans written files via gitleaks (preferred) or fallback regex for API keys, tokens, passwords. 0 = success (warning only)
PostToolUse Write|Edit|MultiEdit audit-log.sh Appends JSONL record to .nana/audit.jsonl: timestamp, tool name, file path. Requires jq. 0 = success (always)
PostToolUse Bash post-commit.sh Detects git commit (not amend/fixup). Writes .dev-wiki/.pending-commit sidecar JSON. Emits [dev-wiki:post-commit]. 0 = success (advisory)
PreCompact — pre-compact.sh Reads dev-wiki state and active-phase.md. Outputs structured summary injected into compacted context. 0 = success (always)
Stop — check-tests-were-run.sh If Python files were modified, checks if pytest was run. Blocks stop if not. 0 = allow, 2 = force continue
Stop — enforce-loop.sh Checks file-existence exit criteria from spec. Advisories: open tasks, debrief status. Events logged. 0 = allow, 2 = block (global hook)
Stop — py-review-stop.sh Command hook: prompts a 6-point review only when Python changed; guards against the stop-loop. 0 = allow, 2 = force continue

Hook Data Flow

  Claude Code invokes a tool (Write, Edit, Bash, etc.)
       │
       ├── PreToolUse hooks receive:  { "tool_name": "Bash", "input": { "command": "..." } }
       │     └── block-dangerous-bash.sh reads .input.command, pattern-matches
       │
       ├── Tool executes
       │
       └── PostToolUse hooks receive: { "tool_name": "Edit", "input": { "file_path": "..." } }
             ├── auto-ruff-format.sh reads .input.file_path, runs ruff if .py
             ├── scan-secrets.sh reads .input.file_path, scans content
             └── audit-log.sh reads .input.file_path + .tool_name, appends JSONL

5. Quality Signals

Error Handling

  • install.sh: upfront source validation (fail-fast before any copy), venv creation with graceful fallback (memory is optional), pip install failure warns but continues
  • sync-rules.sh: validates AGENTS.md exists (exit non-zero with stderr), validates target directory is writable before any writes
  • Hooks: all PostToolUse hooks exit 0 on error (non-blocking) — writes should never be blocked by hook failures. PreToolUse block-dangerous-bash uses exit 2 for intentional blocks only.
  • MCP registration: idempotent JSON merge handles 3 cases (no file, partial, complete) without data loss

Idempotency

  • install.sh: re-running produces identical results — file copies overwrite, venv reuses existing, JSON merge preserves other mcpServers entries
  • sync-rules.sh: re-running overwrites outputs with same content (deterministic from AGENTS.md)
  • MCP JSON merge: overwrites only the memory key — other MCP servers untouched
  • Venv bootstrap: skips venv creation if .venv/bin/python3 already exists, only runs pip install

Safety Boundaries

  • CI secret scan: gitleaks-action as final barrier before merge

  • Session-start hook: each context source independently optional — missing files silently skipped

  • scan-secrets: falls back from gitleaks to regex if gitleaks not installed
  • Venv bootstrap: warns and continues if python3 -m venv unavailable — memory is optional
  • Memory server fastembed: try/except guarded — embedding features degrade to text-only
