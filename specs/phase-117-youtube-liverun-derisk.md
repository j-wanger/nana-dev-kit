# Spec: Phase 117 — YouTube apparatus first-contact (derisk the mock-vs-real gap + harden for real tracks)

## Objective
Before committing to the full frozen live measurement (deferred to Phase 118), cheaply derisk the dominant risk that the Phase-116 apparatus — proven only on a mock that grounds *by construction* — over-drops genuine quotes on real Sonnet-4.6 output and real (often unpunctuated auto-caption) tracks. Add the minimum telemetry to make a smoke run informative (per-call token/cost capture, per-reason drop surfacing, a reformatting-vs-fabrication drop sub-classification), harden the acquisition path the mock never exercised, keep all verbatim transcript text inside the gitignored boundary (ToS), then run 1–2 real search-query-selected videos (quarantined from any Phase-118 corpus) on the residential IP and **decide** whether the apparatus is sound enough on real data to warrant the Phase-118 frozen measurement — and exactly what must be hardened first.

## Context
Phase 116 built the acquire→chunk→extract→ground+consolidate core as local gitignored Python apparatus under `companion/research/youtube/` (53/53 pytest green, committed `1fa9de4`). Everything was proven against fixtures + a mocked Anthropic client. The mock (`tests/test_pipeline.py`) returns `words[:6]` verbatim from the chunk it is handed, so **every fixture quote grounds trivially** — the T4 grounding rail has never met real model output. Two Phase-116 residuals are explicitly slated for "the first live run": **A1** misread rate and **A2** dead-letter/uncaptioned rate. This phase is that first contact, deliberately sequenced as a *derisk + harden* increment (maintainer chose smoke-first over building the full frozen rig sight-unseen), because if the apparatus over-drops genuine quotes on real tracks, building the elaborate frozen measurement first would only run a garbage-drop apparatus through an expensive ritual. Feasibility gates the measurement; the measurement gates the value/headroom screen (a later rung, NOT this phase).

Design basis: a design workflow (a 3-stance judge panel + 3 adversarial lenses, 43 holes surfaced) produced the hardened plan below. The full frozen pre-registration (corpus freeze, A1 human-adjudication rubric, all pass/fail thresholds) is a Phase-118 artifact; Phase 117's job is to make that measurement *worth running* and *interpretable*.

## Scope
### In scope
- `companion/research/youtube/**` — telemetry-only instrumentation (usage/cost capture + `$2/video` kill-switch; per-reason drop surfacing; preflight chunk-count print), acquisition-path hardening (`fetch_segments` blind-retry fix; 200-empty soft-block detection; exhaustive exception→outcome taxonomy incl. `AgeRestricted`), a `harness117.py` smoke runner (catch-and-classify wrapper; reformatting-vs-fabrication drop diagnosis; pacing + circuit-breaker; verbatim-quote sidecars under gitignored `run117/`), a real-model adversarial fixture, and their pytest coverage.
- `.dev-wiki/**` planning + `.dev-wiki/phase-117/` **aggregates-only** (rates, counts, SHA-256 — never verbatim quotes), `.claude/rules/active-phase.md`, `specs/phase-117-*.md`.
- The live smoke drive itself (1–2 videos) is **manual-drive** on the maintainer's residential IP with `ANTHROPIC_API_KEY` set.

### Out of scope
- Any change to shipped kit code, `app/`, `templates/`, `install.sh`, or any security/engine surface.
- **The Phase-116 grounding rail is BYTE-FROZEN:** `ground.py`, `normalize.py`, `consolidate.py`, `schema.py` are not edited this phase (a `git diff` asserts it). All telemetry/diagnosis is added in `extract.py` closures, `ingest.py`'s return dict, and the NEW `harness117.py` — never in the rail.
- The full frozen live measurement (frozen corpus, A1 human rubric, pre-committed thresholds + fail-actions, controls-first M1–M8) — **Phase 118**.
- whisper.cpp ASR fallback (still deferred; uncaptioned → dead-letter, as Ph116).
- The headroom/amplifier screen ("does the retrieved content beat a bare Opus") — a later rung; feasibility must land first.
- Fixing the rail's punctuation-vs-auto-caption behavior itself IF the smoke test reveals it: diagnosis is in scope; a *rail change* is a Phase-118 (or follow-on) task with its own freeze, not a byte-freeze violation slipped in here.

## Approach
A telemetry-and-hardening layer wrapped strictly *around* the frozen rail, then a small manual smoke drive whose only job is to make the two Ph116 residuals (A1/A2) and cost **interpretable on real data**.

**1. Telemetry (the enabling change).** `_complete` currently discards `msg` — so `msg.usage` (tokens) and `msg.stop_reason` (truncation) are lost and cost is unmeasurable. Thread usage out of the closure; accumulate per-video cost at the pinned Sonnet-4.6 rates ($3/1M input, $15/1M output); raise `BudgetExceeded` at `$2/video` (mid-loop kill-switch, no completion marker — consistent with C3); surface `ground()`'s per-reason drop counts on `run_pipeline`'s return (today collapsed to `len(drops)`); print the preflight chunk count before the paid loop.

**2. The load-bearing diagnostic — reformatting vs fabrication.** `ground()` emits a single `quote-not-in-chunk` for BOTH an invented span AND a real span the model repunctuated/de-fillered (the punctuation-preserving match-normalization, kept strict by the Ph116 anti-fabrication revert, will not match an auto-caption's unpunctuated text against a model quote that added commas/periods/expanded contractions). `harness117` re-tests every dropped quote under a **diagnosis-only** punctuation-stripped normalization (never used for grounding): `present-modulo-punctuation` = benign reformatting; `absent-even-stripped` = candidate fabrication. Without this split, an apparatus over-drop is indistinguishable from a genuine thin video — the exact C1/Ph80 "silent drop reads as thin video" failure.

**3. A real-model adversarial fixture (pre-run prediction).** A mock `complete_fn` returning quotes with the transformations a real model applies (added trailing/internal punctuation, an expanded contraction, a leading/trailing ellipsis, curly quotes) PLUS one genuinely-fabricated span. Pin, before any live fetch, which `ground()` keeps vs drops and which the diagnosis buckets as reformatting vs fabrication — converting "the rail behaves on real output" from an untested assumption into a committed expectation, so the live drop-rate is interpretable against a known reformatting baseline.

**4. Acquisition hardening (the untested real-world surface).** `fetch_segments`' blanket `except Exception → api.fetch()` blind-retries the endpoint on block/no-caption classes, doubling endpoint hits exactly when throttled and hiding the true first exception from the classifier. Re-raise `TranscriptsDisabled`/`NoTranscriptFound` (no-captions) and `RequestBlocked`/`IpBlocked` (endpoint-error) WITHOUT a second hit; wrap only shape-normalization. Capture raw HTTP status + body byte-size so a 200-empty soft-block on a known-substantial video is distinguishable from a genuine empty caption track. Make the exception→outcome taxonomy exhaustive over the pinned `youtube-transcript-api` version (add `AgeRestricted`; `except Exception → unclassified` so no mid-batch traceback burns the run).

**5. ToS containment (a correctness fix, not a choice).** All verbatim-quote-bearing artifacts (chunk sidecars, telemetry rows carrying quotes, any A1 review rows) live ONLY under gitignored `run117/`. `.dev-wiki/phase-117/` (which IS tracked) carries aggregates + SHA-256 hashes ONLY — a `grep` gate asserts no committed file contains a `source_quote`.

**6. IP protection.** Inter-fetch cooldown (jittered) between every fetch; a circuit-breaker that halts on any `IpBlocked`/`RequestBlocked` or 2 consecutive endpoint-errors (record remaining as not-run). Even at N=1–2 this is the discipline that scales to Phase 118.

**7. The smoke drive + decision.** Manual-drive 1–2 search-query-selected (biased toward a likely auto-captioned creator — stresses both A2 and the punctuation gap in one video), quarantined from any Phase-118 corpus (no contamination of a later freeze). STOP-and-report after the FIRST video before the second. Record real per-video cost, chunk count, outcome_class, the reformatting-vs-fabrication drop split, and whether genuine concepts grounded. Decide: go/no-go on the Phase-118 frozen measurement + the hardening list + the recommended Phase-118 pre-registration parameters.

## Domain Research Questions
1. On a real auto-caption (unpunctuated) track, what fraction of a real model's "verbatim" quotes drop as `quote-not-in-chunk`, and what is the reformatting-vs-fabrication split of those drops? (Is the strict punctuation-preserving normalization a yield-killer on the generated track?)
2. What does one real Pi/agent-setup video actually cost on Sonnet-4.6, and how often does `stop_reason==max_tokens` truncate a concept-dense chunk to an empty parse (max price, zero yield)?
3. Does a search-query-selected video from the topical long-tail come back captioned at all, and does the hardened classifier cleanly separate no-captions from a residential-IP soft-block?

## Constraints (CRITICAL)
- **Rail byte-freeze (load-bearing).** `ground.py`/`normalize.py`/`consolidate.py`/`schema.py` are byte-unchanged this phase — a `git diff --quiet` on the four files is an exit criterion. Telemetry/diagnosis/hardening live only in `extract.py`, `ingest.py`, `acquire.py`, and the new `harness117.py`. If a real fix to the rail is indicated by the smoke result, it is a *named Phase-118 task with its own freeze*, never slipped in here.
- **ToS containment (load-bearing).** No committed file (esp. under the tracked `.dev-wiki/phase-117/`) contains a verbatim `source_quote` or transcript context window — a `grep` gate asserts it before any commit; verbatim text lives only under gitignored `run117/`.
- **Drop signal must be interpretable (C1/Ph80).** A `quote-not-in-chunk` drop MUST be sub-classified (reformatting vs fabrication) before any drop-rate is read; a silent over-drop must never be allowed to read as "thin video." A stream of probe-aborts (`CalibrationError`) on real code/emoji/multilingual content is a brittleness RED FLAG, not a benign exclusion — >1 probe-abort STOPs and reports.
- **Cost cliff + kill-switch.** `$2/video` mid-loop kill-switch from captured `usage`; the preflight chunk count printed before any paid call; `--confirm` not used in the smoke run so the (Ph116) call ceiling cannot be waived. A budget-abort is a recorded finding (true cost right-censored / cost model wrong), NOT a silent exclusion.
- **IP protection.** Inter-fetch cooldown + circuit-breaker on block/2-consecutive-endpoint-errors; the smoke run confirms a residential (not VPN/cloud) egress before fetching.
- **No contamination.** The smoke videos are quarantined by explicit ID and MUST NOT enter any Phase-118 frozen corpus (seeing their output would break the anti-retrofit freeze).
- **Manual-drive.** Live network/API runs on the maintainer's residential IP with `ANTHROPIC_API_KEY`; deterministic tests use fixtures + a mocked client (no network in the test path).

## Success Vision
The maintainer points the hardened apparatus at one real Pi-setup video and gets back a telemetry row that says, concretely: this cost $X; of the concepts extracted, Y% dropped, and the split is *reformatting* (the punctuation normalization is too strict for auto-captions — fix before scaling) vs *fabrication* (the rail is doing real anti-hallucination work); genuine concepts DID ground on a real auto-caption track (or did not, and here is why). No verbatim transcript reached git. The grounding rail was never touched. On that evidence the maintainer decides — not vibes — whether the full frozen Phase-118 measurement is worth building, and with what hardening.

- [ ] `python -m pytest -q -k "pacing or circuit or probe_abort_tripwire"` — inter-fetch cooldown fires; the circuit-breaker halts on a block / 2 consecutive endpoint-errors; >1 probe-abort trips the STOP tripwire.

## Checkpoints
- After the ToS-containment + rail-byte-freeze proof lands (T4): STOP and report — the containment + freeze are the phase's load-bearing gate before any live fetch touches transcript data.
- After the FIRST smoke video (before the second): STOP and report — a systematic apparatus bug must not burn both fetches; and if the drop is dominated by *reformatting* (not fabrication), that is the go/no-go signal itself.
- If >1 probe-abort, or a residential-IP block, or a budget-abort fires: STOP and report before any further fetch.

## Assumptions
- The mock-vs-real gap (rail never met real model output; strict punctuation normalization vs unpunctuated auto-captions) is the dominant risk and is efficiently derisked by 1–2 real smoke videos before the full rig. If false (the gap is minor and the real risk was elsewhere): the smoke run still yields cost + a real drop baseline, and Phase 118 proceeds with that evidence.
- The reformatting-vs-fabrication drop sub-classification makes the smoke test diagnostic (distinguishes an apparatus over-drop from a genuine thin-video/dead-letter signal). If false (the split itself is ambiguous on real data): that ambiguity is itself the finding and routes a rail-normalization task into Phase 118.
- Telemetry + acquisition hardening can be added without destabilizing the byte-frozen grounding rail. If false (a hardening genuinely needs a rail change): STOP — it becomes a named Phase-118 rail task with its own freeze, not a silent edit here.
- ToS containment (verbatim quotes only under gitignored `run117/`) fully preserves the non-redistribution posture. If false (`.gitignore` regresses): the `grep`/`git check-ignore` gate fails the phase before any commit.
- **Search-query corpus frame** (maintainer chose this over channel-seed): a topical-search selection surfaces the uncaptioned/auto-caption long-tail harder than curated channels — the regime where both A2 and the punctuation gap bite — so the smoke video is a stronger stress test. If false (search-query is too noisy a proxy for the eventual feed): revisit the frame at the Phase-118 freeze, when it actually gates a scale decision.
- **Solo + mandatory clean-context LLM inversion cross-check** (run outside the kit, per Ph80) is adequate to resist single-rater self-judgment for the smoke eyeball and pre-forms the Phase-118 A1 approach. If false (single-rater bias survives even the cross-check): Phase 118 escalates to a second human rater / Cohen's-kappa.
