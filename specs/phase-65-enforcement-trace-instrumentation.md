# Spec: Phase 65 — Enforcement-Trace Instrumentation + Eval-Apparatus Disposition

## Objective

Build the structured, fail-open enforcement-firing substrate the gated hooks currently lack — so a *future* phase can measure whether enforcement components actually change an agent's actions — and execute the eval-apparatus disposition the Phase-63 eval-validity verdict prescribes. No scorer ships this phase; this is measurement + cleanup, not a new gate.

## Context

Phase 63's harness assessment produced an eval-validity verdict: `instrument: mixed`. The deterministic binary corpus (`make eval`, ~52 scenarios — pipes a tool-event through a hook, asserts exit code/output) is sensitive and trusted as the contract gate. The two LLM-judge evals (`eval/comparison/` A/B/C clean-room, `eval/reasoning/` 25-scenario judge) are blind-by-construction: their net-zero deltas sit inside their own run-to-run noise, so a useful feature and a worthless one produce the same observable. The verdict proposed a non-blind replacement keyed on *observed component actions* — "did-a-component-fire-and-change-an-action."

An adversarial approach-review (confirmed against the files) killed a scored-fixture-replay v1 as **corpus-duplication**: the corpus `lifecycle` category already replays ordered hook-event sequences and already toggles the `.claude/enforce` marker across steps (`lifecycle-spec-enforcement-flow` is block→allow), so an action-delta assertion is strictly weaker than what the corpus already pins. The honest, available increment is the **measurement substrate**, not a scorer — and it is genuinely missing: of the gated hooks, only `enforce-spec`/`enforce-loop`/`enforce-memory` write structured records to `.dev-wiki/enforcement.log`; `block-dangerous-bash`, `detect-loop`, `dev-wiki-scope-check`, `check-tests-were-run` (and the `cognitive-readiness` advisory) emit nothing. The scorer that consumes this substrate is deferred to Phase 66, gated on real dogfood signal accruing.

Two latent bugs in the *existing* three loggers must be fixed before propagating the pattern to more hooks (else the phase widens their blast radius): unescaped JSON interpolation, and a non-atomic read-modify-write truncation that races under concurrent fires. And `.dev-wiki/enforcement.log` is currently **git-tracked** in this repo and absent from `.gitignore` (it is the lone `M` file at session start). It is not `cp -r`'d anywhere — `.dev-wiki/` is created per-project at runtime by `dev-init`, the log is created by the hooks' `>>`, and a project's root `.gitignore` is seeded by `py-init`/`ts-init` *appending* lines (the `.nana/` idiom). So the runtime-churn/activity-leak fix is two-part: untrack it here (`.gitignore` + `git rm --cached`), and add the same append line to `py-init`/`ts-init` so consuming projects ignore it from the start.

## Scope

### In scope
- A single hardened enforcement-firing logging pattern emitting one atomic JSONL record per fire: `{schema_version, ts, hook, action, reason, phase}`, where `action ∈ {allow, block, advisory, skipped}` and `reason` is a controlled-vocabulary short string (never raw user input).
- Retrofit the 3 existing loggers (`enforce-spec`, `enforce-loop`, `enforce-memory`) onto the hardened pattern: `jq --arg` (no string interpolation), atomic append, truncation decoupled from the hot path, exit-code-neutral logging, `phase` tag, `schema_version`.
- Wire the pattern into the currently-silent **lifecycle-enforcement** hooks that make an agent-action decision: `dev-wiki-scope-check`, `detect-loop`, `check-tests-were-run`. Committed instrumented set = these 3 + the 3 existing loggers (`enforce-spec`, `enforce-loop`, `enforce-memory`) = **6 hooks**.
- Gate firing-logging on the existing lifecycle markers — **OR** semantics: log when `.dev-wiki/` is present **OR** `.claude/enforce` (project or `$HOME`) is present — so projects that have not opted into the lifecycle neither pay the cost nor leak data, while a hook like `detect-loop` (gated on global `$HOME/.claude/enforce`, often with no `.dev-wiki/`) is still captured. No new opt-in marker. All 6 instrumented hooks are lifecycle-class, so this gate never silences a firing the substrate is meant to capture.
- Untrack `.dev-wiki/enforcement.log` (+ `.tmp`/rotation siblings): add to this repo's `.gitignore` and `git rm --cached`; add the same append line at all four `py-init`/`ts-init` gitignore sites (the `.nana/` idiom, present in both the new-project and existing-project path of each skill) so consuming projects ignore it from creation. There is no `templates/.gitignore` and none is created.
- A new test (wired into `make test`) asserting, per instrumented hook: (a) a synthesized event yields a well-formed JSONL record (`jq` parses; required keys present); (b) **fail-open** — with the log path forced unwritable, the hook returns its correct exit code (block stays a block); (c) **injection-safe** — an event whose recorded field contains `"`/`\`/newline still yields valid JSONL; (d) the log path is gitignored.
- Eval-apparatus disposition (Part B): retire `eval/comparison/`'s confounded A-vs-C arm (apparatus removed, tombstone note retained, clean A-vs-B note kept); demote `eval/reasoning/` to calibration-only (made unreachable from `make eval`/`make test`, still runnable on explicit invocation, README relabeled); delete the orphaned `eval/reasoning/with-self-dialogue-{inline,subagent}/` dirs.
- Regenerate `templates/.claude/settings.json` via `make template` only if registration changes (expected no-op — no new hooks).

### Out of scope
- The **scorer** / with-without-feature delta computation (Phase 66, gated on accrued signal).
- The `audit-log` PostToolUse hook and `.nana/audit.jsonl` — a *different* observable (per-tool-call audit), its own roadmap item; not conflated or wired here.
- Rewriting the 2 historical `debrief`-schema lines already in `enforcement.log` (no active writer exists; strict schema lets a future consumer filter by `action` presence).
- A logging framework / sourced log-level config / rotation daemon — resist infrastructure for a scorer that hasn't specified its needs (see Constraints).
- New hooks, new registrations, reasoning-quality measurement (remains unmeasured — acknowledged, not filled).
- Instrumenting `block-dangerous-bash` (safety-class, not lifecycle-class — its efficacy is already corpus-covered, and it reads bash command bodies, the worst secret-leak surface), `post-commit` (a commit-detection trigger, not an agent-action gate), and `cognitive-readiness` (a session-start nudge with no allow/block/advisory decision). Excluded by the inclusion criterion.
- Recording raw bash command bodies or raw file paths (privacy — see Constraints).

## Approach

Standardize enforcement-firing logging across the gated hooks by hardening the existing `log_event` pattern (the kit's idiom — small duplicated helpers, pure-bash, sub-50ms) and propagating it. Reuse the existing `enforcement.log` channel and `{hook,action,reason}` schema, extended with `phase` and `schema_version`; do not introduce a new file and do not conflate the per-tool-call `audit-log`. Logging is strictly subordinate to enforcement: a hook's decision and exit code must be byte-identical whether logging succeeds, fails, or is absent. The disposition is pure subtraction guided by the verdict. Name everything honestly — this is instrumentation, not an "eval"; after this phase, reasoning-quality remains unmeasured, and that is acceptable because the demoted judge measured nothing either.

### Domain Research Questions
1. **Shared sourced lib vs. duplicated hardened snippet?** A sourced `lib/log.sh` is DRY but adds a `source` per hook — a new failure mode (a missing/unreadable lib aborts every hook under `set -e`) and startup cost. The kit currently duplicates a 6-line helper across 3 hooks. Which better satisfies the subtraction test and the fail-open + reads-like-surrounding-code constraints? If a lib is chosen, how is its own load made fail-open?
2. **What is the recorded-fields contract that is both privacy-safe and analyzable?** Hooks read different input shapes (`.input.file_path`, raw `"command"`, `.tool_uses[]`). Raw input is unsafe (secrets) and heterogeneous. What normalized, non-sensitive `reason`/`target` vocabulary (matched-rule-id, path-class, tool-name) makes a future delta computable without leaking command bodies?
3. **Retention/truncation policy for a measurement log.** The committed inclusion criterion is settled in Scope ("a lifecycle hook that emits an allow/block/advisory decision about an agent action" → the 6-hook set). The genuinely open design call is retention: in-hook `tail -n 500` read-modify-write both races under concurrent fires and taxes the hot path, and ~500 lines is ~a day of a busy session — too short to be longitudinal signal for the Phase-66 scorer. What bounds the file without racing or discarding the records being measured — size-based rotation (`enforcement.log.1`), out-of-band rotation, or `flock`-gated truncation? Decide it.

## Constraints (CRITICAL)

- **Constraint: logging is exit-code-neutral by construction — prevents the substrate from converting a block into a non-block.** The hooks run under `set -euo pipefail` and block via `exit 2`; if a log step (`>>`, `mv`, `date`, `jq`, disk-full, read-only FS) fails, `-e`/`pipefail` can abort the hook *before* its real `exit`. Adding logging to `block-dangerous-bash` could let `rm -rf` through on a full disk. Every log call must be guarded (`... || true`) and the decision `exit N` computed and emitted independent of logging outcome.
- **Constraint: never hand-roll JSON; never record raw user input — prevents unparseable JSONL AND secret exfiltration.** Emit via `jq -nc --arg`; any field is a controlled-vocabulary token (rule-id, path-class, tool-name), never a raw path or bash command. Bash commands routinely carry secrets (`export TOKEN=…`); a logged command body in a readable/tracked file is an exfiltration vector — the same class `scan-secrets.sh` exists to stop.
- **Constraint: one atomic record per fire; truncation off the hot path — prevents losing the very firings being measured.** Use a single `>>` append of one newline-terminated line (atomic under `PIPE_BUF`). Do not do in-hook read-modify-write truncation (it races under concurrent fires and can abort under `set -e`); bound the file by size-based rotation or out-of-band, preserving longitudinal records.
- **Constraint: `enforcement.log` is runtime state, not source — prevents fleet-wide git churn and activity leakage.** Untrack it here (`.gitignore` + `git rm --cached`) and add the `.dev-wiki/enforcement.log` append to `py-init`/`ts-init` (the `.nana/` idiom) so consuming projects ignore it from creation — there is no `templates/.gitignore` and the fix must not invent one. A test asserts it is gitignored here.
- **Constraint: firing-logging is bounded to opted-in lifecycle projects — prevents cost/leakage in projects that never asked to be measured.** Log only when `.dev-wiki/` is present OR `.claude/enforce` (project or `$HOME`) is present (OR, not AND — else a global-enforce hook like `detect-loop` is silenced where it has no `.dev-wiki/`); neither marker → no record (intended, documented), not a gap.
- **Constraint: template edits are quarantine-first migrations.** `modules.json` is the hook source-of-truth; `templates/.claude/settings.json` is generated via `make template` — never hand-edited. Prevents cascade-failure blast radius + settings drift.
- **Constraint: `make eval` count must not move — prevents shifting the trusted contract gate the next phase will measure against.** Disposition touches no corpus `scenario.json`; record the before/after count explicitly.
- **Constraint: no scorer, no gate, no "eval" naming for the substrate — prevents shipping corpus-duplication ceremony / overclaiming a reasoning-quality gate that doesn't exist.**
- **Constraint: demote ≠ delete ≠ retire — prevents collapsing distinct dispositions into `rm -rf`.** Comparison harness = retired (removed from gating, rationale preserved). LLM-judge eval = demoted (code retained, made non-gating, relabeled calibration-only — assert both unreachable-from-`make` AND still-runnable-explicitly). Orphaned records = deleted only when zero inbound references exist in the working tree.
- **Constraint: no deletion without a full-tree reference sweep — prevents dangling citations.** Before removing any basename, `grep -rn` it across Makefile, scripts, tests, modules.json, MANIFEST, `.claude/rules`, `.dev-wiki`, `wiki`, `eval`. `eval/research-measurement/results.md` and `eval/comparison/` are cited by activated working-knowledge — a dangling `source:`/`[[…]]` link is an abort condition.

## Success Vision

Every gated enforcement hook leaves an honest, uniform, atomic, fail-open trail of *when, why, and under which phase* it fired — across the four real states (blocked / warned / passed-silently / skipped-because-disabled) — so a future phase can ask "did this component change an action?" from observed data rather than a judge's opinion. The instrumentation is invisible in the happy path (no latency, no behavior change, no leaked secrets) and silent on failure (never breaks a hook, never corrupts the log). The existing three loggers come out *more* correct than they went in (injection-safe, race-free, gitignored). The eval apparatus is smaller and more honest: the confounded comparison arm is retired with a tombstone explaining why, the blind judge is unmistakably a calibration tool that never gates, and dead experiment records are gone — with nothing pretending to measure reasoning quality that doesn't.

## Exit Criteria (machine-checkable)

- [ ] Functional, per instrumented hook (the test covers all 6 — the 3 existing + 3 new): a synthesized event produces a JSONL record that `jq -e 'has("hook") and has("action") and has("reason") and has("phase") and has("schema_version")'` accepts. (This functional check, not a `grep schema_version` count, is the presence gate — a comment mention can't false-positive it.)
- [ ] Fail-open: `bash tests/test_firing_log.sh` asserts each block hook still returns exit 2 / each allow path still returns 0 under BOTH (a) an unwritable log path (`chmod 000` the dir) and (b) a failing `jq`/`date` stubbed on `PATH` (the mid-pipe `pipefail`-abort path that `chmod` does not exercise).
- [ ] Injection- AND exfiltration-safe: (a) an event whose recorded field contains `"`, `\`, and a newline still yields `jq . <log>` exit 0 on every line; (b) an event whose input contains `export TOKEN=sekret` produces a logged `reason` that does NOT contain `sekret` (controlled-vocabulary invariant — proves no raw input is recorded, not merely that it parses).

## Checkpoints

- **After the hardened pattern + ONE hook instrumented + the fail-open/injection tests pass** (the riskiest unit, and the moved falsification checkpoint): report — confirm logging cannot alter a hook's exit code or corrupt the log *before* propagating to the rest. If the fail-open contract can't be met cleanly, STOP.
- **Before deleting any `eval/` apparatus:** confirm `results/` is empty AND the reference sweep is clean — explicitly grep `tests/test_templates.sh` (the file most likely to dangle: it exercises `run-eval.py` and references `self-dialogue-injection.md`/`traces/` but NOT the `with-self-dialogue-*` dirs), plus `working-knowledge.md`/`active-knowledge.md` (`eval/comparison/` and `eval/research-measurement/results.md` are cited there). A dangling reference → STOP and reconcile.
- **If instrumenting a hook requires changing its decision logic** (not just adding a guarded log call) → STOP and report: the log must be additive, not a refactor of the gate.

## Assumptions

- `enforcement.log` is the right shared channel (3 hooks already use it). If a hook can't reach `.dev-wiki` (runs outside a lifecycle project): the helper no-ops — logging is best-effort, absence is acceptable and documented.
- The `phase` tag is available from `.claude/rules/active-phase.md`. If absent (uninstalled/between projects): tag `"phase":"unknown"`, never fail.
- The 2 historical `debrief`-schema lines have no active writer (confirmed). If a current writer is found during implementation: route it through the hardened pattern or to its own channel — don't leave a heterogeneous schema.
- `eval/comparison/results/` is empty and the A-vs-C apparatus is unreferenced by any test. If a test/eval-runner depends on a deletion target: STOP, reconcile before deleting.
- `detect-loop`/`check-tests-were-run`/`dev-wiki-scope-check` make loggable allow/block/advisory decisions (verified: each has distinct decision branches and none currently logs). If one turns out to be a pure trigger with no decision: exclude it and note why — don't force a meaningless record.
- `jq` is available where these hooks log (it is already a hard dependency of the existing loggers). If absent: the hook fail-opens as today (`exit 0`) and writes NO record — a jq-free hand-rolled line would violate the no-hand-rolled-JSON constraint, so the gap is accepted and documented (the absence is itself honest information: jq-missing → gate skipped, unlogged).
