# Spec: Phase 101 — Harder-corpus contract-vs-spec fidelity screen (edge-screener)

## Objective

Re-run the Phase-100 contract-vs-spec fidelity screen on a **harder corpus** where bare prompts plausibly **fail for an integrity reason** — real code-development tasks built by stubbing integrity-critical functions in **edge-screener** — to test whether a contract (naming the integrity invariant as a deterministic guardrail) keeps a delegated `opencode` worker more on-outcome than a prose spec or a bare prompt, on subtle-integrity work a bare prompt overlooks but **held-out** un-foolable tests catch.

## Context

Phase 100 ([[contract-fidelity-screen]]) returned a clean amplifier-null — but **ceiling-saturated**: a capable `opencode/big-pickle` worker aced four toy coding tasks regardless of arm, so the screen tested "does a contract help where a worker already succeeds?" (no) rather than "where it would otherwise **fail**." Phase 100 routed the harder-corpus question forward. This phase takes it on with `edge-screener` (`/Users/jwang/edge-screener`) — a stock-screener backtesting platform whose entire thesis is *un-foolable integrity*: a no-lookahead firewall (decision-lag k→k+1, no same-bar booking), cost-accuracy, point-in-time survivorship. Its ~50 rigorous tests (several explicitly anti-gaming) are the deterministic ground truth; the domain creates genuine failure headroom because a plausible-but-subtly-wrong implementation passes a casual eye but fails the integrity tests.

Direction gate (2026-06-22, ledger Phase-101, all_accept:false): **A1 accept** (mandatory difficulty-calibration pilot; no in-band task → informative null); **A2 reject** bug-injection → **from-scratch stub**; **A3 accept** (per-run edge-screener copy reusing its `.venv`; smaller corpus 3-4 tasks × n=3-5); **A4 accept** (edge-screener is the base). Reuses the frozen Phase-100 harness; the new design is the corpus + the worker-in-edge-screener workspace.

## Scope

### In scope
- A new gitignored apparatus dir `companion/research/contract-screen-hard/`: a **from-scratch-stub corpus** (each task stubs one integrity-critical edge-screener function — signature + docstring only — with a held-out scorer test, a seeded reference solution, and a seeded known-wrong solution), the per-run edge-screener-copy runner, a byte-frozen pre-registration, results, and a verdict.
- A **mandatory difficulty-calibration pilot** that classifies *why* the bare arm fails (by the failing integrity assertion), keeping only tasks where bare fails *for the integrity reason*, stably.
- The frozen 3-arm screen (bare/spec/contract, information-parity) on the kept corpus in per-run edge-screener copies, scored **primarily** by the held-out integrity test(s) (deterministic, ship-blocking) and **secondarily** by the cross-model Claude judge (descriptive), via a **forked, byte-frozen `analyze-hard.py`** (deterministic-primary headline, `MIN_CORPUS=3`, `n=3` count-gate) that reuses Phase-100 `analyze.py`'s effect-form math but with this phase's pinned parameters.
- A mechanical **verdict** — contract-vs-spec on the harder corpus (now with bare-arm failure headroom) — OR, if <3 tasks land in-band, an **informative null** with the per-task bare evidence.

### Out of scope
- Any shipped-kit change — the kit already shipped `check-fidelity.py` (Phase 100); **this phase ships nothing**, it is a measurement re-run. No `scripts/`/`modules.json`/hook/test changes.
- Mutating the real `/Users/jwang/edge-screener` (per-run throwaway copies only; the original is read-only, checksum-verified).
- Pillar 2 (downstream-worker fleet); a new contract-format design.
- Re-deriving the Phase-100 harness — `check-fidelity.py`/`analyze.py`/the judge are reused; only the corpus + workspace are new.

## Approach

Build a candidate set of **function-level** stubs (function granularity keeps floor risk manageable): integrity-critical edge-screener functions with ONE strong, namable invariant (the backtest decision-lag, cost application, PIT membership), each carrying (1) the existing rigorous test as the **held-out scorer** — which checks *functional correctness AND* the integrity invariant, so a vacuous/do-nothing stub fails functionally; (2) the existing real implementation as the **seeded reference solution** (proving a fix exists — not floor-by-construction); (3) a **seeded known-wrong solution** (the canonical lookahead / survivorship-included / cost-dropped variant) the held-out test MUST fail (controls-first: a test that passes the seeded bug is a dead instrument). For each task the worker gets a per-run copy of edge-screener with the function body stubbed and the held-out scorer (and its discriminating literals anywhere reachable) removed; arms at information parity render the SAME signature+docstring and differ only in whether the integrity invariant is named (bare = none; spec = objectives prose; contract = the invariant as a deterministic guardrail, *without* the test's operative literals). The pilot runs bare on each candidate, classifies the failure mode, and keeps the discrimination band; freeze the kept corpus + payloads + scorers + the pinned worker model/version + n=3 + the forked `analyze-hard.py`; run the full screen; score deterministically (primary) + judge (secondary); read the frozen `analyze-hard.py` rule mechanically.

### Domain Research Questions
- Which edge-screener functions have a **single, namable** integrity invariant a bare prompt plausibly violates, a held-out test that catches the violation **generatively** (not a fixture a stub could special-case), and a real reference solution? (Candidates: the no-lookahead decision-lag, cost application, PIT membership.)
- How is the invariant made **truly** unreachable in the worker's copy — the test file removed AND no sibling test / conftest / fixture / README / type-stub re-encoding its discriminating literals?
- What bare fail-rate band (and how many bare pilot runs per candidate) distinguishes "integrity-hard" from floor-by-noise, requiring the *same* integrity assertion to fail across runs?

## Constraints (CRITICAL)

- **Failure must be an INTEGRITY failure, stable** — a bare failure from import/signature/timeout/API confusion means the contract has nothing to save (the experiment measures noise). Guard: the pilot records the failing assertion ID per bare run; keep a task only if ≥2 of N bare runs fail the **same integrity assertion**, and reject tasks whose bare failures are dominated by non-integrity errors. A "no scorable implementation" run (no edit to the target function / no diff) is a distinct infra outcome, never a silent FAIL.
- **Deterministic test PRIMARY (ship-blocking); judge SECONDARY (descriptive)** — the held-out integrity test is the verdict; the LLM judge can never overturn it. Pre-registered disagreement rule: judge-PASS but test-FAIL = FAIL (a judge false-positive, reported); test is ground truth, judge is color. Implemented by the **forked `analyze-hard.py`** — Phase-100 `analyze.py` is judge-primary and is NOT reused verbatim; only its effect-form math carries over. (This flips Phase-100's judge-headline because here the integrity tests are un-foolable.)
- **Contract-arm floor guard (machine-checkable)** — a task where bare AND contract both fail (the worker reaches the fix in NO arm) is the "floored corpus dressed as a verdict" risk. Guard: for a contract-vs-spec VERDICT (not a null), ≥1 in-band task must show the contract-arm pass-rate exceeding the bare-arm by the frozen effect form; if every in-band task has the contract arm also at floor, the result is the **informative null**. The reference-solution-passes control proves a fix *exists*, NOT that *this worker reaches it* — those are different, so the floor guard is applied to the contract arm's observed rate, not the reference.
- **Held-out scorer validated against a seeded known-wrong reference (controls-first)** — each held-out test MUST FAIL the canonical bug (lookahead / survivorship-included / cost-dropped) AND PASS the real reference, recorded before the screen. A test that passes the seeded bug is a dead instrument → that task is rejected; clean-on-seed across all tasks aborts the phase.
- **Held-out truly unreachable (whole reachable tree)** — removing the test file is necessary but not sufficient; the invariant's discriminating literals must be absent from every reachable file in the worker's copy (sibling tests, conftest, fixtures, README, stubs). Guard: per run, a grep gate over the copy fails setup if the discriminating tokens appear; the held-out test is applied only in a separate scoring copy.
- **Contract names the invariant, not the test's literals** — the contract may state the property ("decisions at date r use only bars dated ≤ r; weights decided at k earn returns at k+1") but must not contain the held-out test's operative literals (threshold values, the boundary date, the firewall constant). Guard: a pre-registered leakage diff of the frozen contract text against the held-out test source rejects any shared discriminating token.
- **Information parity** — bare/spec/contract render the identical signature + docstring and differ ONLY in whether the invariant is named; the contract adds the invariant-as-guardrail, not extra task information. Guard: byte-frozen payloads with a diff-able parity assertion (`strip_guardrail(contract)==spec`, `strip_objectives(spec)==bare`).
- **Calibration gates the corpus, both arms** — only tasks where bare fails-for-integrity-but-isn't-floored enter the corpus; a task at floor for the contract arm too (too hard for any arm) is excluded by the same band logic (it biases toward null). If <3 land in-band → the **informative null**, never a contract-vs-spec conclusion from a degenerate corpus.
- **The real edge-screener is never mutated** — every run/score uses a throwaway copy; the original is read-only. Guard: checksum the real repo before and after the full run set and fail loud on any delta; assert the worker/scoring CWD is a copy outside it; `git -C /Users/jwang/edge-screener status` clean post-phase.
- **Frozen before scored runs (anti-retrofit)** — kept corpus, payloads, held-out scorers, reference + known-wrong solutions, the pinned worker model/version, **n pinned at 3** (not a post-hoc range), and the forked `analyze-hard.py` (det-primary, MIN_CORPUS=3, n=3 count-gate) are byte-frozen (sha256 `.frozen`) BEFORE the scored screen; the pilot precedes the freeze (it selects the corpus) and is recorded. Guard: `shasum -c .frozen` after. No re-pick / contract-enrich / band-loosen / rule-edit after seeing results.
- **Claim scoped + worker pinned** — results are a function of *these* integrity properties and *this* worker (opencode/big-pickle, version recorded). Guard: the verdict scopes the claim to "contract vs spec vs bare, on these edge-screener tasks, with this worker," never "contracts keep AI workers faithful" in general.
- **nana-isolation + judge independence** — the worker runs in edge-screener (nana context cannot leak); the judge is arm-blind, given only task+implementation, no experiment framing, and (being secondary) cannot manufacture a contract effect. Apparatus gitignored, ships nothing.

## Success Vision

An honest answer to the question Phase 100 couldn't reach: on tasks hard enough that a bare prompt *actually fails for an integrity reason*, does a contract that names the invariant keep the worker more faithful than a spec or bare prompt? Excellence is a verdict made trustworthy by proven bare-arm failure headroom (the pilot shows bare fails the integrity assertion, stably), un-foolable held-out tests validated to catch the canonical bug, a contract that names the property without leaking the test, information parity, a deterministic primary metric the judge can't override, and the frozen rule — read mechanically whichever way it falls. A **clean "no discriminating corpus constructible"** is a valid success (it bounds where contracts can be measured at all). What excellence is NOT: a contract "win" from a leaked test, a payload gap, a vacuous-pass, or a floored corpus dressed as a verdict.

## Exit Criteria (machine-checkable)

- [ ] Controls-first on the instrument: `companion/research/contract-screen-hard/pilot.md` records, per task, that the held-out scorer PASSES the seeded reference solution AND FAILS the seeded known-wrong solution; a task failing either is absent from the frozen corpus (clean-on-seed everywhere → phase aborted, recorded).
- [ ] Calibration with failure-mode stability: `pilot.md` lists each candidate's bare runs with the failing assertion ID, and each kept task has ≥2/N bare runs failing the **same integrity assertion** (non-integrity-dominated tasks rejected).
- [ ] Held-out unreachable: per scored run, a recorded grep gate confirms the held-out test file AND its discriminating literals are absent from the worker copy's reachable tree.
- [ ] Contract-leakage check: the frozen contract payloads share no discriminating literal with the held-out test source (recorded diff).
- [ ] Information parity: frozen arm payloads satisfy `strip_guardrail(contract)==spec` and `strip_objectives(spec)==bare` (byte-equal).
- [ ] Either (a) ≥3 in-band tasks (`analyze-hard.py` MIN_CORPUS=3, n=3) → the frozen screen ran (3-4 tasks × 3 arms × n=3 in per-run copies), `verdict.md` records the mechanical contract-vs-spec verdict (deterministic primary: per-arm distributions + effect form + disposition; judge secondary/descriptive), the bare arm shows real integrity failure (rate <1.0 on ≥1 task), AND a contract-vs-spec VERDICT (vs the null) requires ≥1 in-band task with contract-arm rate > bare-arm rate by the frozen effect form (else → informative null); OR (b) <3 in-band → `verdict.md` records the informative null with the per-task bare evidence.
- [ ] Structural required-field scan (not pure prose-trust, mirroring Phase-100): a field check confirms `pilot.md` carries per candidate { task-id / bare-failing-assertion-id / disposition (in-band|floor|ceiling) / reference-passes / known-wrong-fails } and `verdict.md` cites { the frozen rule / per-arm distributions / the effect form / the disposition }.
- [ ] Frozen instrument intact: `shasum -a 256 -c companion/research/contract-screen-hard/.frozen` passes.
- [ ] Real codebase unmutated: a recorded checksum of `/Users/jwang/edge-screener` is identical before and after the run set; `git -C /Users/jwang/edge-screener status --porcelain` empty.
- [ ] No kit change: `git -C /Users/jwang/nana-dev-kit status --porcelain` shows only `.dev-wiki/`+`specs/`+`.claude/rules/`; `make test` ALL-PASS; `make eval` 50/50; drift 0.

## Checkpoints

- After the candidate set + held-out scorers + seeded reference + seeded known-wrong are built: report the controls-first result (each scorer passes the reference AND fails the known-wrong) — the instrument is alive before any worker run; a task whose scorer can't catch its canonical bug is dropped.
- After the calibration pilot, BEFORE freezing: report the per-task failing-assertion classification + in-band/floor/ceiling disposition. If <3 tasks fail-for-integrity-stably → STOP and record the informative null. If ≥3 → freeze and proceed.
- After one scored pilot run per arm on an in-band task: confirm the held-out test scores it (in the scoring copy), the worker edited the target function in its copy, and the real repo checksum is unchanged — before the full n.
- If `opencode` cannot develop/run in an edge-screener copy, or the invariant cannot be made unreachable, or all scorers pass their seeded bug: STOP and re-scope/record the limitation rather than ship a leaked, vacuous, or non-runnable screen.

## Assumptions

- `opencode` can develop in a per-run edge-screener copy and the held-out test runs there via the reused `.venv`. If false: STOP — re-scope the workspace before the screen.
- ≥3 integrity-critical functions have a single namable invariant + a generative held-out test (validated against a seeded bug) + a real reference. If false: if <3 land in-band, the informative null stands (do not pad with weak tasks).
- A bare prompt genuinely fails some in-band tasks *for the integrity reason*. If false (bare honors integrity even on hard tasks): the result is "contract adds nothing — capable worker honors integrity unprompted even on hard tasks," strengthening (not contradicting) the Phase-100 null; report it as such.
- The invariant can be made truly unreachable. If false for a given task (re-encoded across the copy's tests/fixtures): drop that task — drops merely shrink the corpus (→ the <3 informative null if too many fall). Only if NO candidate can be made unreachable (the iterate-to-green problem is across-the-board) is it the STOP-and-report-limitation case.
- Per-run copies + scoring env are affordable at 3-4 tasks × n≥3. If false: drop n before the bare-baseline arm; scope the claim to the reduced power.
