# Spec: Phase 100 — Contract-vs-Spec Fidelity Screen (rung-C pillar-1)

## Objective

Measure empirically — not by reasoning — whether a frozen **contract** (outcome objectives + deterministic, machine-checkable guardrails) keeps a real downstream worker (the `opencode` CLI) more on-outcome than a prose spec or a bare prompt, and whether a **deterministic** fidelity-check suffices or a **neural judge** catches fidelity failures the guardrails miss. Build the deterministic fidelity-check (the scoring instrument AND the one shippable artifact) and use it — with a marked neural-judge arm — to score a pre-registered, controls-first 3-arm screen on real `opencode` runs. The verdict decides whether a contract artifact ships.

## Context

This is **pillar 1 of the rung-C contract-driven-delegation program** — the kit's own thesis (deterministic validators at boundaries) applied one level up: a frozen contract governs a *delegated, non-watched* worker so it stays truthful. Pillar 3 (the Phase-99 direction dashboard) shipped first; pillar 2 (a 24/7 `opencode` worker fleet) is a later phase. The Ph97 frontier verdict located the kit's moat in *opinionated, value-capturing guardrails*; rung-C applies that thesis to delegation.

At the Phase-100 direction gate (2026-06-22, ledger Phase-100, all_accept:false) the maintainer made the central calls *empirical, not assumed*: **A1** (does a contract artifact earn its complexity over reusing the existing `success:`/`/spec` criteria) and **A2** (is a deterministic spine enough) came back **don't-know — resolvable only by running real workers** ("need to run actual test scenarios with opencode workers using different contract vs spec variants"); **A3** rejected seeded-only validation (a real worker IS the instrument); **A4** accepted shipping, scoped to the *check*; **R1** added a marked neural-judge arm alongside the deterministic scorer; **R2** set 3 arms + a frozen decision rule; **R3** ships the check and defers the contract-schema shape to the verdict. So Phase 100 is a **measurement phase**, the rung-C analogue of the amplifier-screen lineage (Ph70/71/77/78/80): pre-registered, controls-first, verdict read mechanically.

A documented hazard governs the method: measurements run **inside** nana-dev-kit are contaminated because its always-loaded `.claude/rules/` leak answers to any worker/judge in-directory (Ph80 was declared instrument-dead for exactly this). The worker and judge must see **only** the variant input, in an isolated workspace outside the repo tree.

## Scope

### In scope
- **The deterministic fidelity-check (shippable, A4/R3):** `scripts/check-fidelity.py` — reads a *contract* (outcome objectives + deterministic guardrails, each a command + expected exit/output, reusing the existing `success:`-criterion shape) and a captured worker-output workdir, runs every guardrail, emits a mechanical PASS/FAIL fidelity verdict with per-guardrail detail. A `make` target; `tests/test_contract_fidelity.sh` registered in `make test`.
- **The measurement apparatus (gitignored `companion/research/contract-screen/`, like Ph97/98):** a byte-frozen pre-registration (arms, corpus, n, scoring + aggregation rule, decision rule, controls); an `opencode` runner that executes each arm-run in its own isolated workspace; a dual scorer (the deterministic check above + a calibrated neural judge); a results table; a mechanical verdict.
- **The screen run:** 3 arms (bare-prompt / spec / contract) × a fidelity-discriminating task corpus × n≥3 runs, on real `opencode` workers, each run scored by both scorers.
- **The recorded verdict:** contract-vs-spec on the fidelity metric (A1) + deterministic-vs-judge agreement (A2), read mechanically from the frozen rule, with the claim scoped to the pre-registered corpus.

### Out of scope
- The contract-schema's **shipped** shape — an OUTPUT of the verdict (ships in-phase only if conclusive, else routes to a gated build phase). No precommitment, and **no designing/polishing a contract-format spec** this phase (that is pillar-2 build work).
- Pillar 2's 24/7 `opencode` worker fleet and any reusable worker-orchestration layer — the runner is the minimum needed to produce scoreable runs, nothing more.
- Any neural judge in the **shipped** check — the judge is a *measurement arm only*, never a shipped dependency.
- Refactoring existing scripts/generators; any `modules.json` / hook / settings change; any commit or push of `companion/research/` (gitignored, local-only).

## Approach

Build the deterministic fidelity-check first — it is needed under **either** A1 outcome (Option A's contract or Option B's runner-only), so building it precommits to nothing. Its guardrails reuse the kit's existing deterministic-criterion shape rather than inventing a parallel one, and must themselves be deterministic (a given worker output always yields the same verdict). It is the screen's deterministic scorer and the phase's shippable artifact.

Then run the screen as frozen apparatus: pre-register the three arm payloads (held to **information parity** — same outcome intent, differing only in the structure-under-test), the task corpus, n, the per-guardrail-vs-all-or-nothing aggregation rule, the decision rule, and the controls; freeze byte-for-byte **before any run**; execute each arm-run in its own throwaway workspace outside the repo tree where the `opencode` worker sees only the variant input; capture each workspace as a snapshot and score it with the deterministic check and the neural judge. The bare-prompt arm is the amplifier-null guard; a leak-probe task is the contamination control; deliberately violating and **guardrail-gaming** outputs are the controls-first seeds. Worker non-determinism is handled by n≥3 and a variance-aware decision rule that requires the inter-arm delta to exceed within-arm spread.

### Domain Research Questions
- What makes a task **fidelity-discriminating** — an outcome both machine-checkable (so a deterministic guardrail can score it) AND carrying a subjective quality dimension (so the judge *can* disagree)? Include at least one **gaming** case where literal guardrails pass but the outcome is violated (stubbed function, hardcoded expected string) — the case that tests whether the judge earns its place.
- How is the `opencode` worker provably isolated from nana-dev-kit's always-loaded context — does `--pure` + a scratch CWD outside the tree suffice, or does `opencode` parent-walk to an `AGENTS.md`/config that re-introduces the leak? What isolation makes the leak-probe arm score at chance?
- What minimal calibration keeps the neural judge honest given the kit's self-grading-inflation finding (Ph44-50) — exemplar anchoring, a cross-model judge, a seeded gaming-case it must catch, and judge-repeat-variance as a reported floor?
- What fidelity **metric + aggregation** turns per-run guardrail/judge outcomes into a per-arm score the frozen rule compares — and how are infra failures (worker never ran) excluded rather than scored as zero?

## Constraints (CRITICAL)

- **Information parity across arms** — bare/spec/contract must convey the *same* outcome intent and differ only in the structure dimension under test; otherwise the screen measures payload size, not contract structure. Guard: the three payloads are byte-frozen in the pre-registration with a diff-able parity note asserting equal task information; a reviewer can confirm the only delta is the guardrail/structure.
- **Non-leaking workspace + leak-probe control** — the worker and judge see ONLY the variant input, in a workspace outside the repo tree (no symlink/parent-walk back). Guard: a **leak-probe arm** — a **multi-option (K≥4) question** whose answer appears ONLY in nana-dev-kit's docs — MUST land within the chance band (≈1/K); the pre-registration fixes K and a **binding void threshold** (an accuracy at/above it declares the run instrument-dead and void, Ph80). A binary (K=2) probe is insufficient (it cannot resolve leak from luck at low n). The harness asserts the effective CWD contains none of the project's loadable instruction files.
- **Frozen before runs (anti-retrofit)** — the pre-registration (arms, corpus, n, scoring, aggregation, decision rule, controls) is byte-frozen (sha256 `.frozen`) BEFORE the first run; the verdict reads the frozen rule with no post-hoc edits. Guard: a drift check asserts `sha256(pre-registration) == .frozen`; any later edit breaks the match.
- **Controls-first, per-guardrail and per-scorer** ([[HEU-012]]) — for the deterministic check: a seeded HONORED output every guardrail passes, and per guardrail a seeded VIOLATED output it MUST fail (a guardrail with no failing fixture is rejected — clean-on-seed = dead, applied per-rule not just per-run); a malformed contract the check rejects loud (non-zero + stderr). For the judge: a seeded **gaming** output where the deterministic check PASSES but the judge MUST flag a citable defect, and a seeded honored output it MUST pass. Guard: `tests/test_contract_fidelity.sh` asserts the deterministic exit codes; the apparatus records the judge's control results.
- **Judge falsifiability** — "the neural judge caught what the deterministic check missed" counts only when the disagreement is (a) stable across the judge's own repeat runs on the same output AND (b) backed by a citable, human-checkable defect; bare judge-repeat variance (same input) is reported as a control floor. Guard: the apparatus runs the judge ≥3× per output and records stability + the cited defect; unstable or uncitable disagreements do not count.
- **Worker-ran vs unfaithful** — an `opencode` run that errored, rate-limited, or produced no output is an infra failure, NOT a fidelity score of 0. Guard: the runner records run status; infra-failed runs are excluded and re-run to reach n, never aggregated as fidelity zero.
- **Check determinism + isolated workspace per run** — the shipped check's guardrails carry no timestamp/file-ordering/network/absolute-path dependence (same output → same verdict); each arm-run executes in its own throwaway workspace and is scored against a captured snapshot, never shared live state. Guard: a guardrail re-run on the same fixture yields the identical verdict; arms never share a workdir.
- **Mechanical verdict + pinned effect floor** — contract-vs-spec and deterministic-vs-judge agreement are computed from the frozen rule. "Exceeds within-arm spread" is pinned in the pre-registration to a **concrete form** (non-overlapping per-arm ranges OR delta ≥ k·pooled-SD, k frozen) — not left as a vague phrase a weak early-frozen rule could satisfy — and a **minimum corpus size** is frozen below which the ONLY permissible verdict is "underpowered / pilot-scoped, routed forward." Guard: the verdict cites per-arm distributions + the frozen threshold + the effect form; a positive control (a known-margin synthetic) confirms the comparator before the real read. Underpowered deltas are reported as null, never upgraded post-hoc.
- **No contract-schema precommitment** — the shipped check runs under a minimal contract shape (`{objectives, guardrails}`) that does NOT presuppose A1's answer; the *shipped* schema decision waits for the verdict. Guard: the check + tests pass on the minimal shape.
- **Judge is measurement-only** — the neural judge never enters the shipped check or any shipped path. Guard: `scripts/check-fidelity.py` has no LLM/network dependency; the judge lives only in `companion/research/`.
- **Apparatus gitignored** — `companion/research/contract-screen/` is never committed or pushed (local-only, like Ph97/98); no stray transcript/`.gitkeep` lands in the shipped tree. Guard: `git check-ignore` confirms; `git status` shows nothing under it; `make test`/drift see only the shipped check.
- **House-style + surgical** — the check is self-contained, matches the existing `scripts/` style, adds no shared helper for one caller, rewrites nothing. Guard: drift 0; diff ⊆ the new files.

## Success Vision

An honest verdict the maintainer can act on: a clean, mechanically-read comparison of whether a contract keeps a real worker more on-outcome than a spec (and whether a deterministic check suffices or a judge earns its place), produced by an instrument whose seeded controls — bare-baseline, leak-probe-at-chance, per-guardrail negatives, a gaming case, judge-variance floor — prove it would have caught a dead screen, a leak, or a payload-size confound. The shippable fidelity-check fails loud on garbage, is itself deterministic, and ships clean (`make test` green, drift 0). Excellence includes a verdict that comes back **"contract adds nothing over spec → collapse to runner-only"** or **"deterministic suffices → drop the judge"** — a null is a real result because the controls and the freeze make it trustworthy, and the claim is scoped to the pre-registered corpus, not over-generalized from one task. What excellence is NOT: a contract artifact shipped on enthusiasm before the screen, a polished contract-format built this phase, or a verdict softened after seeing the numbers.

## Exit Criteria (machine-checkable)

- [ ] `bash tests/test_contract_fidelity.sh` passes: a seeded HONORED worker output → check exits 0 (PASS); per guardrail, a seeded VIOLATED output → check exits non-zero (FAIL) naming the failed guardrail; a malformed contract (bad JSON / missing required field) → check exits non-zero with a stderr message. (Clean-on-seed, or any guardrail lacking a failing fixture, fails the test.)
- [ ] Check determinism: re-running the check twice on the same fixture yields byte-identical verdicts (`diff` of two runs is empty).
- [ ] `make test` ALL-PASS with `test_contract_fidelity.sh` registered; `make eval` denominator unchanged (50/50); `bash scripts/check-install-drift.sh` reports drift 0.
- [ ] `scripts/check-fidelity.py` has no network/LLM dependency, proven by an **AST import scan** (robust to aliasing / `from x import y`, unlike a loose grep): `python3 -c "import ast,sys; t=ast.parse(open('scripts/check-fidelity.py').read()); m={a.name.split('.')[0] for n in ast.walk(t) if isinstance(n,ast.Import) for a in n.names}|{n.module.split('.')[0] for n in ast.walk(t) if isinstance(n,ast.ImportFrom) and n.module}; sys.exit(1 if m & {'requests','anthropic','openai','httpx','urllib','urllib3','socket','http'} else 0)"` exits 0. Plus a runtime control: `tests/test_contract_fidelity.sh` runs the check to completion with no API key set / network unavailable (offline behavior, not just absent import spellings).
- [ ] Pre-registration frozen before runs: `companion/research/contract-screen/pre-registration.md` and `.frozen` exist, `sha256(pre-registration.md) == .frozen`, and `git check-ignore companion/research/contract-screen/pre-registration.md` confirms it is gitignored; `git status --porcelain companion/research/` is empty.
- [ ] Arm payloads frozen with an information-parity note: the pre-registration contains the three byte-frozen payloads and an explicit assertion they carry equal task information, differing only in the structure under test.
- [ ] Leak-probe control: the pre-registration defines a multi-option (K≥4) probe whose answer lives ONLY in nana-dev-kit's docs and a binding void threshold; the recorded results show leak-probe accuracy within the chance band (≈1/K) — at/above the frozen threshold → run declared instrument-dead and void.
- [ ] Gaming control: the results record at least one output where the deterministic check PASSED but the judge flagged a citable defect (evidence the judge arm is non-vacuous), and the judge's repeat-variance floor.
- [ ] The screen ran: `companion/research/contract-screen/results.md` records all 3 arms × n≥3 runs with per-run deterministic + judge scores and run status (infra-failed runs marked excluded, not scored 0).
- [ ] Structural gate on the apparatus outputs (a format check so the document-attestation criteria are not pure prose trust): a required-field scan confirms `results.md` carries, per run, the fields arm / deterministic-score / judge-score / judge-repeat-variance / run-status, plus a leak-probe-score field; and `verdict.md` cites the frozen decision rule + per-arm distributions + the effect form.
- [ ] The verdict is recorded mechanically: `companion/research/contract-screen/verdict.md` states the contract-vs-spec call (A1, with inter-arm delta vs within-arm spread) and the deterministic-vs-judge agreement (A2), each from the frozen rule, with the contract-schema disposition (ship in-phase | route to build phase) and the claim scoped to the corpus.

## Checkpoints

- After the fidelity-check + controls pass (seeded honored / per-guardrail violated / gaming / malformed): report — instrument-alive gate before any screen run.
- After the pre-registration is frozen and BEFORE the first run: STOP and confirm the freeze (sha recorded) and information parity — no run may precede the freeze.
- After a single pilot run per arm (n=1): verify the leak-probe scores at chance, the corpus produces gradable + sometimes-disagreeing scores, and infra failures are detected (not scored 0). If isolation is unproven or the corpus is non-discriminating, STOP and fix before the full n≥3.
- If `opencode` runs prove too noisy/expensive to reach n≥3, or fidelity is not deterministically scorable on the corpus, or the leak cannot be closed: STOP and surface (down-scope per the ledger fallbacks) rather than ship a vacuous or leaked screen.
- At the verdict: report the mechanical read; the contract-schema ship/route decision is the maintainer's call on the recorded evidence.

## Assumptions

- `opencode` is scriptable headless (`opencode run --pure --format json`, v1.17.3 confirmed on PATH). If false: STOP — the real-worker instrument is the phase; re-scope to a different worker runner before proceeding.
- Worker isolation from the always-loaded context is achievable and verifiable (leak-probe scores at chance). If false (the leak cannot be closed): the screen is instrument-dead per Ph80 — STOP; do not report a leaked result as a verdict.
- Fidelity is deterministically scorable on a constructible corpus, with at least one gaming case the judge can catch. If false: the deterministic check cannot grade — STOP and reduce to a judge-only metric, recording that A2 could not be tested deterministically.
- The neural judge can be calibrated to stable, citable agreement on the seeded controls. If false: drop the judge arm, report "deterministic-only (judge un-calibratable)", and let A2 stand on the deterministic scorer alone.
- Real-worker runs at n≥3 × 3 arms are affordable in time/cost. If false: drop n before dropping the bare-baseline arm; report the reduced power and scope the claim accordingly.
- The corpus is representative enough for the intended claim. If it is below the pre-registered minimum corpus size: the verdict is explicitly pilot-scoped and routed forward — a sub-minimum (e.g. single-task) screen may NOT be reported as a contract-vs-spec conclusion (one task proving "contract more faithful" does NOT establish the format generalizes).
