# Spec: Phase 82 — QA & Verification Sweep (ultracode)

## Objective
Execute a coverage-defined QA and verification sweep over the nana-dev-kit implementation using multi-agent orchestration: every audit area is verified by an executed command with captured evidence, every confirmed defect is fixed surgically with repo and installed copies converged, and "verified clean" is mechanically distinguishable from "never checked."

## Context
nana-dev-kit is a Claude Code harness kit (25 skill dirs, 18 hook scripts in templates/.claude/hooks/ plus 2 session-start.d curator modules, a vendored Python MCP memory server, install.sh driven by modules.json, a templates/.claude/ tree copied to ~/.claude on install). make test (20 shell test scripts, ~450 assertions) and make eval (52 binary scenarios) are green at baseline. The project's history contains a recurring "silent breakage" class: components that pass presence-style checks but never fire (registered-but-dormant hooks; a wrong-CWD MCP config that broke memory for 30+ phases; an eroded line cap no test asserted). Project discipline: deterministic validators over LLM judges, verify-firing-not-presence (HEU-012), subtraction test, surgical changes only. The kit develops in templates/ but RUNS from ~/.claude — a drift seam with a dedicated checker (scripts/check-install-drift.sh); a 6-file pre-Phase-81 drift was found and resynced during Phase 82 planning (drift count now 0). Phase 81 just shipped the assumption-approval gate (dev-plan/dev-debrief skill changes + append-only .dev-wiki/assumption-ledger.md + NO-LLM scripts/check-assumption-ledger.sh); Phase 82 is its first live dogfood, so gate artifacts are quarantined (see Constraints). The frozen measurement apparatus (eval/amplifier/*, eval/assumption-screen/) is freeze-constrained by five decision articles — findings there are FILED, never fixed. This sweep hunts what the green deterministic suites do NOT cover.

## Scope
### In scope
- Seven audit areas with fixed row labels for the verification matrix: (1) `wiring` — registration integrity (modules.json ↔ filesystem ↔ generated templates/.claude/settings.json, bidirectional per test_registration.sh's invariant); (2) `firing` — hook functional positive-control checks, not presence (per tests/test_hook_firing_coverage.sh's union definition); (3) `companions` — skill ↔ companion-file integrity (frontmatter parent/referenced_at, SKILL.md Read-path resolution); (4) `schema` — single-source consistency (the `## Ledger schema` block in scripts/check-assumption-ledger.sh as sole ledger-schema source; the scope-tagged hooks array in modules.json as sole hook-registration source; any contract documented in two places); (5) `drift` — installed-copy divergence (~/.claude vs templates/, direction-of-authority decided per file), INCLUDING a retrospective audit of the planning-time 6-file resync (confirm from git history that the overwritten installed copies corresponded to pre-Phase-81 template versions, not unbackported hot-fixes — the pre-resync ~/.claude state is otherwise unrecoverable); (6) `coverage` — registered components with no functional test (the silent-breakage class); (7) `docs` — accuracy of README.md, MANIFEST, templates/AGENTS.md, and .dev-wiki/_ARCHITECTURE.md counts/claims vs reality (kit-root AGENTS.md does not exist; templates/AGENTS.md is the docs target; known unconfirmed candidates: _ARCHITECTURE.md says "17 hooks"/"26 skill dirs" vs counted 18/25); (8) `usage` — utilization audit (maintainer-raised at the direction gate): per shipped component group, deterministic evidence of REAL use vs dead weight — memory DB row count and last-write date (server known underutilized: ~11 entries since Phase 49, prior 30-phase wrong-CWD breakage), enforcement.log volume/recency, .nana/audit.jsonl presence, assumption-ledger rows, plus a READ-ONLY look at /Users/jwang/edge-screener (the one real consuming project) for consuming-side utilization. Under-used components are FILED as subtraction-review candidates feeding the deferred Phase-79 prune-on-value item (re-trigger: "a hook is found never-firing") — never removed in-phase.
- Surgical fixes to confirmed in-scope defects in kit-managed files (listed in modules.json/MANIFEST), including the cascade each fix requires (MANIFEST md5 lines, make template regeneration, drift-test rerun).
- A verification matrix artifact at eval/qa-sweep/verification-matrix.md with exact column order `| area | command | evidence | verdict |` and lowercase verdict enum `clean` / `defect-found` / `deferred` / `instrument-dead`. One row minimum per audit area; per-fix sandbox/diff evidence is appended to the owning row's evidence column (or a `## Fixes` section in the same file).
- Filing out-of-scope or high-risk findings as deferred items in .dev-wiki/_CURRENT_STATE.md `## Blockers and Open Questions`, each named by the matrix row's area + a short slug so the linkage is greppable.

### Out of scope
- New features, new hooks, new machinery of any kind (subtraction posture; QA only).
- Harness-efficacy measurement (unmeasurable in-kit — Phase 80 INSTRUMENT-DEAD precedent).
- The frozen measurement apparatus (eval/amplifier/*, eval/assumption-screen/) — read-only; findings filed.
- memory_server upstream divergence beyond wiring checks (vendored; near-zero divergence by design).
- Consuming-project drift (deferred Phase-76 item B; different provenance model).
- Performance optimization, refactors, style cleanup — every changed line must trace to a confirmed defect.

## Approach
Multi-agent orchestration with subagents demoted to CANDIDATE-GENERATORS only (maintainer-rejected assumption at the direction gate: in-kit subagent context leak cannot be made acceptable for verification — clean context is structurally impossible here since worktrees carry the same .claude/rules/). A read-only audit fan-out (one agent per audit area) returns candidate findings with proposed reproduction commands; NO subagent transcript is ever evidence. Every verdict — `clean` AND `defect-found` — is established solely by a deterministic command the ORCHESTRATOR executes itself and whose output it captures into the matrix: defects are confirmed only by orchestrator reproduction, clean verdicts only by orchestrator-run checks. The leak therefore only biases candidate RECALL (doc-based phantom candidates die at reproduction; undocumented misses are backstopped by the deterministic checkers and the coverage area). Fixing is serialized through the orchestrator (single writer). Zero confirmed defects is a valid success: the phase deliverable is the coverage matrix, not a defect count — agents must not manufacture findings to justify the sweep.

In-phase fix boundary (pre-registered): a confirmed defect is fixed in-phase iff it is in a kit-managed file AND the fix is S/M-sized AND its blast radius is covered by existing tests (the relevant test script reruns green). Kit-managed means: tracked in the kit git repo — EXCLUDING the frozen apparatus (eval/amplifier/*, eval/assumption-screen/), .dev-wiki/assumption-ledger.md (gate-flow-only writer), and anything under ~/.claude not listed in modules.json/MANIFEST; in-repo docs (README.md, MANIFEST, templates/AGENTS.md, .dev-wiki/_ARCHITECTURE.md count claims) ARE kit-managed and evidence-backed count corrections there are in-boundary. Coverage-area exception (pre-registered): for a `coverage` finding — a registered component with no functional test — the blast-radius condition is unsatisfiable by definition, so writing the missing S/M functional test IS the in-phase fix (the functional-smoke invariant mandates it; tests are not "new machinery"); coverage gaps needing L-sized test work are deferred. Everything else — frozen-apparatus findings, L-sized fixes, fixes whose blast radius has no test — is filed as deferred. Rejected alternative (recorded): permanently extending make test directly as the phase, skipping the sweep — rejected because the sweep is what PRODUCES the verified gap list test-writing consumes; the coverage exception lets the sweep close the S/M portion in the same pass. When two findings prescribe conflicting fixes for the same file (e.g., opposite direction-of-authority calls), the orchestrator decides on documented evidence (git history, hot-fix provenance); if still ambiguous, defer both and file.

## Constraints (CRITICAL)
- Hook fixes are sandbox-first: apply and exercise in mktemp -d, piping a real event JSON and asserting BOTH the allow path (exit 0) and the block/advisory path (exit 2 or expected [nana:] stderr), BEFORE touching any live copy (~/.claude/hooks/ or .claude/hooks/) — prevents the documented enforce-spec.sh self-lockout class.
- Firing-evidence standard: a hook/component counts as verified only with a positive control (input constructed to force the blocking/advisory output, exit code or stderr string asserted). "Ran without error" is presence-style evidence and is rejected — prevents vacuous verification (fail-open hooks exit 0 on missing markers/malformed stdin).
- Orchestrator-only verdicts: NO subagent output (prose OR reported command transcript) is admissible evidence for ANY matrix verdict. Subagents propose candidates with reproduction commands; the orchestrator executes every evidence command itself — reproduction for `defect-found`, checks for `clean` — and records its own captured output. Prevents both the Phase-80 recitation class and the fabricated-transcript hole that prose inspection cannot detect (HEU-012 applied to the matrix's own rows; maintainer-rejected the leak-is-acceptable assumption at the gate).
- Checker self-validation, bounded: each checker cited as the evidence for a `clean` matrix row — and ONLY those checkers, once per checker — must first demonstrate detection of one seeded synthetic defect in a scratch copy (a synthetic drifted file for check-install-drift.sh; check-assumption-ledger.sh's own --selftest satisfies this internally; a deliberately unregistered hook in a scratch modules.json for test_registration.sh). A checker that never demonstrably fired proves nothing. If a checker fails its seeded control: STOP the affected area, record verdict `instrument-dead`, continue other areas — prevents broken-glob-reports-clean-forever.
- ~/.claude ownership boundary: never delete or whole-file-overwrite a path under ~/.claude not listed in modules.json/MANIFEST; settings.json changes flow ONLY through scripts/register-settings.py idempotent merge, with a before/after jq diff showing only intended keys — prevents destroying user-owned MCP servers/permissions/non-kit hooks.
- Concurrency model: audit and verification agents are READ-ONLY (no Edit/Write to the repo or ~/.claude); all fixes are applied serially by the orchestrator after the verification barrier; two findings naming the same file are merged into one fix (conflict rule in Approach) — prevents last-writer-wins silent overwrites on a shared tree.
- Phase-81 quarantine: .dev-wiki/assumption-ledger.md is READ-ONLY to the sweep (the only legitimate writer is the dev-plan/dev-debrief gate flow); suspected gate-mechanics defects are confirmed via scripts/check-assumption-ledger.sh --selftest and filed, not hot-fixed — prevents truncating the append-only ledger and conflating gate-dogfood failures with QA findings.
- Fix definition-of-done: direction-of-authority decided per file; templates/ and ~/.claude converged; MANIFEST/make-template regeneration committed in the same change; relevant drift/state tests rerun green — prevents the fixed-in-repo-broken-in-runtime seam (the 30-phase MCP-CWD shape).
- Out-of-scope findings (new-machinery proposals, refactors, upstream memory-server issues, frozen-apparatus defects) are FILED as deferred items, never fixed opportunistically — prevents scope creep past the QA mandate.

## Success Vision
A maintainer reading the verification matrix can answer, for every audit area, "what exactly was run and what came back" — clean verdicts carry the same evidentiary weight as defect findings. Confirmed defects are fixed with both copies converged and the regeneration cascade committed atomically, so no fix exists only in the repo or only in the runtime. Checkers that vouched for cleanliness have each proven they can detect a planted defect. The phase is equally successful at zero defects (trustworthy clean bill) and at N defects (each fixed or deliberately deferred with rationale) — what it cannot produce is an unverifiable "looks fine."

## Checkpoints
- After the audit fan-out completes (before ANY fix): report the full findings list with per-area verdicts; this is the single mid-phase report point.
- If a fix touches an enforcement hook, settings.json merge, or anything under ~/.claude: append the sandbox/jq-diff evidence to the matrix (owning row or `## Fixes` section) BEFORE applying the live change.
- If confirmed defects exceed 10: STOP and re-scope with the user (the sweep found more than a sweep should fix in one phase).
- If any checker fails its seeded-defect self-validation: STOP the affected area, record `instrument-dead`, continue other areas.

## Assumptions
- make test and make eval are green at phase start. If false: baseline repair becomes the phase's first serialized fix; the sweep proceeds only after green.
- templates/ is the direction-of-authority for MOST drifted files, but this is falsifiable per file. If a divergence is an unbackported hot-fix: backport installed → templates instead, and record it in the matrix.
- Audit subagents inherit the kit's always-loaded working-knowledge.md (context leak) and are therefore candidate-generators ONLY; verdict soundness rests entirely on orchestrator-executed deterministic commands. If orchestrator-side execution proves infeasible for some area: that area's verdict is `deferred`, never a subagent-attested `clean`.
- The eight audit areas (including the maintainer-added `usage` utilization area) cover the silent-breakage-and-dead-weight surface that matters. If a hot spot outside them emerges: re-scope at the direction gate before fan-out, or file it deferred mid-phase.
- The ultracode orchestration (Workflow tool) is available and authorized by the user's invocation. If unavailable: fall back to sequential Agent dispatches preserving the same read-only/serial-write contract.
