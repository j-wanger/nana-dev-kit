# Spec: Phase 67 — Long-Cadence Hook Firing Tests + Hook Firing-Coverage Gate

## Objective
Make "every registered hook has a real firing test" a machine-checkable invariant, and fill the firing-test gaps that invariant exposes — closing three deferred Phase-63 remediation-roadmap items (long-cadence firing tests, session-start.d author-global drift, eval/reasoning `.venv` hygiene).

## Context
nana-dev-kit enforces a **functional-smoke invariant** ([[decision:functional-smoke-invariant-rule]], Phase 41): every registered component must have ≥1 functional test that pipes a real event through it and asserts behavior — established after 4 silent breakages each lasting 8–33 phases (a registered-but-broken hook passes a file-existence test while doing nothing; [[HEU-012]]: verify firing, not presence). That invariant is currently held only in prose: nothing *enforces* that each registered hook actually has a firing test. The same class of unguarded convention has eroded repeatedly here (the session-start.sh line-cap drifted 70→137 lines over 30+ phases with no test catching it). The Phase-63 harness assessment left a remediation roadmap; three of its items are now actionable and concern exactly this gap:
- **long-cadence firing tests** — `pre-compact.sh`, `post-compact.sh`, `session-stop.sh` are registered, advisory (always exit 0), fire only at compaction/session-end, and write nothing to enforcement.log by construction, so log-silence is not evidence they work. They have no firing test. (`check-tests-were-run.sh` — listed as a 4th in the roadmap — is already firing-tested at `test_firing_log.sh:150`; the roadmap overstated the gap as 4.)
- **session-start.d author-global drift** — the curator chain (`session-start.sh` → `session-start.d/*.sh`) is copied by `install.sh --project-local`; the plumbing is already correct (lines 89–94 copy `session-start.d/*.sh`), but nothing tests that the copied chain actually runs at the destination.
- **eval/reasoning `.venv` hygiene** — already resolved (`.gitignore` covers it; 0 tracked files); closeable by verification only.

This phase is self-contained and must remain readable after compaction: it adds **tests only** (no new hooks, no behavior changes to existing hooks), plus a roadmap-article reconcile.

## Scope
### In scope
- A coverage meta-test (`tests/test_hook_firing_coverage.sh`) that cross-checks the registered-hook set against a **falsifiable, declared** coverage signal, classifies by hook type, and carries an explicit justified exemption list.
- Firing tests asserting load-bearing side-effects for the advisory long-cadence hooks `pre-compact.sh`, `post-compact.sh`, `session-stop.sh`, plus any additional command-type hooks the meta-test's RED run surfaces as genuinely untested (each either gets a firing test or a justified exemption).
- A small allow/skip-path firing test for `check-tests-were-run.sh` (its block path is already covered; exit-0 branch is not).
- A sandbox `install.sh --project-local` regression test that proves the copied `session-start.d/` curator chain *executes* at the destination (not merely that bytes were copied).
- Wiring each new test script into the `Makefile` `test:` target; reconciling `.dev-wiki/articles/phase-63-remediation-roadmap.md` to mark the three items closed with corrections.

### Out of scope
- Adding, removing, renaming, or changing the behavior of any hook (this phase tests existing registered hooks).
- Any `modules.json` / `settings.json` / `make template` change (no new hooks ⇒ `test_registration.sh` + `test_settings_template.sh` must stay green untouched).
- New eval scenarios (`make eval` stays at its current dynamic count, 52).
- The parked enforcement-scorer, the real-agentic eval, MCP-redundancy, and `/dev-context` naming items (blocked on structural preconditions / other decisions).
- Self-installing project-local hooks into the kit's own repo (duplicates `templates/`, creates drift).

## Approach
Build the gate **RED-first**: the meta-test is written and run *before* the gap is filled, so it reports the authoritative untested set rather than relying on a guessed list. Then fill every gap it surfaces (firing test or justified exemption) until it is GREEN. The meta-test's denominator is the **union** of `modules.json` `.hooks[].script` *and* every `*.sh` under each `project_local.extra_dirs` entry — the `session-start.d/` curators are registered via `extra_dirs`, not `.hooks[]`, and must not escape coverage. Hooks are **classified by type using the predicate the data requires, NOT a literal `type=="command"`**: command hooks have **no `type` field** in modules.json (only `py-review-stop-prompt.md` carries `type:"prompt"`), so the firing-required set is `jq -r '.hooks[] | select((.type // "command") != "prompt") | .script'` unioned with `extra_dirs/*.sh`; a literal `select(.type=="command")` matches zero hooks, empties the denominator, and makes the gate falsely green. The `prompt`-type entry is not executable and requires a **structural** test (file exists, non-empty, valid frontmatter) instead — a machine-provable exemption (`jq '.type=="prompt"'`), not a hand-listed one.

The gate must be **un-gameable**: because the meta-test is self-authored, "exempt everything" would otherwise pass it. So (a) the exemption set is pinned to a literal allow-list in the meta-test and asserted by exact membership + size (a new exemption that isn't machine-justified fails); (b) each exemption must *prove* its reason by command — `prompt`-type via `jq`, any "fired-transitively-by-a-tested-chain" case by pointing at the covering test's declared marker for the parent — an exemption with no verifiable reason fails; (c) the meta-test asserts a **denominator-sanity floor** (the computed union count must equal the expected total — ~17 command + 1 prompt + 3 curators = 21 — and fail if the denominator collapses below it), so a classifier bug that empties the set is caught instead of reported as 100%.

Firing tests must assert the hook's **observable effect**, never exit code alone — an advisory hook gutted to a no-op still exits 0, so exit-code-only "coverage" is satisfied by a broken hook. Every firing test runs in an isolated fixture (`mktemp -d`, `HOME` override, `cd` into the fixture) so hooks that write relative to `$CWD`/`$HOME` cannot mutate the kit's own `.dev-wiki/` or `.nana/`. The installer test installs into a throwaway directory and then *fires* the copied `session-start.sh`, asserting a curator effect appears at the destination.

### Domain Research Questions
1. **What coverage-declaration mechanism is robust *and* falsifiable?** Bare filename grep is empirically useless here (every hook name appears in `test_registration.sh` / `test_settings_template.sh`; invocation uses `HOOK="…"; bash "$HOOK"` indirection). What signal proves a test *fires* a hook and cannot be satisfied by an incidental mention or a comment — e.g. a structured `# fires: <script>` declaration each firing test self-asserts, collected and checked against the registered union, with the declaration's truthfulness anchored by the declaring test actually invoking the script?
2. **Per advisory hook, what is the single load-bearing observable?** (`post-compact` *removes* `.context-warned`; `session-stop` *writes* `.dev-wiki/.session-end` containing `ended:`; `pre-compact` *surfaces* active-phase / next-task content read from fixtures.) And what is the correct **graceful-skip** behavior when the project state those hooks read is absent?
3. **For each command-type hook the RED run flags as untested, is a firing test the right answer, or a principled exemption?** What makes an exemption justified (a real structural reason — e.g. prompt-type, or fired-transitively-by-another-tested-chain) versus "didn't get to it" (which defeats the gate)?

## Constraints (CRITICAL)
- **Exit-code-only assertions are forbidden for firing tests** — a gutted no-op advisory hook still exits 0. Guard: every firing test asserts a stdout/stderr substring or a named file side-effect (created/removed/contains), not just `exit == 0`. The meta-test should reject a "covering" test that only checks exit code.
- **The coverage denominator must be the union of `.hooks[].script` + `extra_dirs/*.sh`** — iterating only `.hooks[]` reports 100% while the 3 `session-start.d/` curators are untested. Guard: assert the union count against the filesystem so a newly added curator dir cannot slip the net.
- **A comment-only / incidental filename mention must NOT satisfy the gate** (falsifiability test). Guard: coverage is proven by a declared marker tied to actual invocation, not `grep -l <name>`.
- **`type:"prompt"` hooks are exempted from firing tests but require a structural test** (file exists, non-empty, valid frontmatter). Command hooks have **no `type` field** — classify with `(.type // "command") != "prompt")`, never a literal `type=="command"` (which matches zero hooks and empties the denominator). Guard: the meta-test asserts a denominator-sanity floor (union count == expected ~21) so a collapsed denominator fails loudly instead of reporting green.
- **The exemption list must be machine-bounded, not prose** — a self-authored gate can "exempt everything" and pass. Guard: pin the allowed-exemption set to a literal in the meta-test and assert it by exact membership + size; each exemption proves its reason by command (`prompt` via `jq '.type=="prompt"'`; transitive-fire via the covering test's declared marker). An exemption that grows or lacks a verifiable reason fails the meta-test.
- **Tests must not mutate the kit's own working tree** — hooks write into `.dev-wiki/` / `.nana/` relative to where they run. Guard: `mktemp -d` + `HOME=$fx` + `cd $fx` isolation (the `test_firing_log.sh` pattern); the kit's own `.dev-wiki/enforcement.log` and `.nana/` must be unchanged after `make test`.
- **The installer test must prove the copied curator chain *executes*, not just that files landed** — a copy can drop the `+x` bit or land curators while the orchestrator that loops them is absent. Guard: fire `session-start.sh` from the install destination and assert a curator effect; also assert copied-set == source-set and executable perms.
- **No new hooks ⇒ no manifest/settings churn** — `test_registration.sh` (bidirectional registration) and `test_settings_template.sh` (drift) must pass unchanged. Guard: adding a test touches only `tests/` + one `Makefile` `@bash` line.
- **`make eval` must stay at its current dynamic count (52)** — no eval scenarios added or removed. Guard: assert the runtime count, never a literal.
- **Firing tests must not hang or leak children** — a hook that reads stdin it never receives blocks; a hook that forks can race the next test. Guard: pipe explicit stdin to every hook; run each firing test (or the hook invocation) under a `timeout`; reap/`wait` any spawned child.
- **The meta-test's failure message must be actionable for the *next* hook author** — point at "add a firing test (and for a new hook, run `make template`)", not just "coverage < 100%", so the gate guides rather than blocks.

## Success Vision
A new contributor who adds a hook and forgets its firing test sees `make test` fail with a message naming the uncovered hook and what to do — the silent-breakage class that cost this kit 8–33 phases per incident becomes impossible to merge. The three long-cadence advisory hooks have tests that would catch a real regression (a deleted breadcrumb, an unwritten `.session-end`, a removed `.context-warned`), not tests that rubber-stamp `exit 0`. The installer's curator chain is proven to run end-to-end at a fresh install, so the Phase-62 curator can never again silently fail to fire in a dogfood environment. The roadmap reflects reality: three items closed, with the corrections (gap was 3 not 4; `.venv` already clean; install plumbing already correct) recorded so a future sweep doesn't re-derive them. The coverage gate itself is honest — it cannot report green while a registered hook is untested, because its denominator is the full union and its coverage signal is invocation-anchored, not grep.

## Exit Criteria (machine-checkable)
- [ ] `bash tests/test_hook_firing_coverage.sh` exits 0 (GREEN) — every firing-required registered hook (union of `.hooks[]` where `(.type // "command") != "prompt"`, plus `extra_dirs/*.sh`) has an invocation-anchored firing test or a machine-justified exemption; the prompt-type hook has a structural test.
- [ ] `tests/test_hook_firing_coverage.sh` denominator is the union: `grep -q extra_dirs tests/test_hook_firing_coverage.sh` (the meta-test references the curator source, not only `.hooks[]`).
- [ ] The gate is un-gameable: the meta-test pins a literal exemption allow-list and asserts its membership/size, AND asserts a denominator-sanity floor — `grep -qE 'EXEMPT|exempt' tests/test_hook_firing_coverage.sh && grep -qE '(-eq|-ge|==) *2[01]|expected.*2[01]' tests/test_hook_firing_coverage.sh` (an exact-count assertion on the ~21-hook union; a classifier bug that empties the denominator fails rather than reports green).
- [ ] Negative control: temporarily adding a bogus uncovered command hook entry (or removing one firing test) makes `test_hook_firing_coverage.sh` FAIL — proven once during T1 and noted in the task log; the gate must reject, not rubber-stamp.
- [ ] `bash tests/test_long_cadence_hooks.sh` exits 0 — asserts the named side-effect for each of `pre-compact` / `post-compact` / `session-stop` (not exit code alone) and a graceful-skip case.
- [ ] `bash tests/test_install.sh` exits 0 with the new assertion: it fires the copied `session-start.sh` in a sandbox and asserts a curator effect at the destination (`grep -q session-start.d tests/test_install.sh`).
- [ ] `make test` exits 0 with all scripts green. (Count of record = the Makefile `test:` target's `@bash tests/*.sh` lines, currently **15**; `helpers.sh` is a sourced helper, not a test. New total = 15 + the new scripts wired in; asserted by the run passing, not a literal.)
- [ ] `make eval` reports 52/52 (`make eval 2>&1 | grep -qE '52/52|52 / 52'`) — dynamic count unchanged.
- [ ] `bash tests/test_registration.sh && bash tests/test_settings_template.sh` both exit 0 — no manifest/settings drift.
- [ ] Repo state clean after tests: `git status --porcelain .dev-wiki .nana 2>/dev/null | wc -l` is 0 after `make test` (tests did not mutate the kit's own state).
- [ ] `grep -c 'CLOSED\|closed (Phase 67)' .dev-wiki/articles/phase-63-remediation-roadmap.md` ≥ 3 — the three items are marked closed with corrections.

## Checkpoints
- **After the meta-test RED run (T1):** report the authoritative untested-hook count and list. If it exceeds ~6 hooks, report the per-hook fire-test feasibility before writing all of them — some may warrant a justified structural exemption rather than a forced low-value test. Proceed autonomously for a small gap; surface a large gap before ballooning the phase.
- **If the meta-test cannot distinguish a genuinely-untested hook from a justified exemption without an unmaintainable allow-list:** STOP and reconsider the coverage-signal design (the gate is worse than useless if it's either always-green or perpetually-red).
- **If `make eval` drifts off 52 or `test_registration` / `test_settings_template` regresses:** STOP and revert — a test-only phase must not perturb registration or the eval count.

## Assumptions
- The advisory long-cadence hooks have a stable, assertable observable effect (stdout marker or file write). If false (a hook's only effect is unobservable in a sandbox): assert the next-best observable and document why, rather than asserting exit code alone.
- `install.sh --project-local` installs CWD-relative to `.claude/hooks/` (verified, line 70) and copies `session-start.d/*.sh` (verified, lines 89–94). If false: the installer test fails loudly and the session-start.d item is reclassified from verify-and-close to a real fix.
- `session-start.sh` sources/loops `session-start.d/*.sh` (the post-Phase-54 template). If false (the template doesn't loop the curator dir): the "fire the chain" assertion fails — that is itself the bug the drift item is about; surface it.
- `eval/reasoning/.venv` is already gitignored with 0 tracked files. If false: add the gitignore line + `git rm -r --cached` as a small extra step (still in scope as the `.venv` hygiene item).
- The grep-inference unreliability is intrinsic (confirmed by 3 probes), so a declared coverage marker is necessary. If a robust inference-only signal turns out to exist: it may be used instead, provided it still fails on a comment-only mention.
