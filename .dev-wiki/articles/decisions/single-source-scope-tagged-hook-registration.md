## Decision

Replace the three disagreeing hook-registration sources with ONE canonical scope-tagged `hooks` array in `modules.json`. Each entry carries `scope: "project" | "global"`. `register-settings.py` filters by scope; the per-project `templates/.claude/settings.json` is a **generated artifact** (project-scoped hooks), regenerated by `make template` and protected by a drift test. The enforce opt-in marker becomes project-reachable (`.claude/enforce` OR `$HOME/.claude/enforce`).

## Context

The C/D stock-screener experiment (Phase 54-56) scored 7.5 with enforcement entirely inactive — enforce-spec never fired. Root cause: enforcement was registered only in global `~/.claude/settings.json`; the test harness's backup/restore wiped global state and enforcement silently vanished. Third instance of the cascade-failure anti-pattern.

Audit of the current tree confirmed three sources that disagree:
- hand-maintained `templates/.claude/settings.json` (9 hooks, no enforcement) — used by py-init `cp -r`
- `modules.json` `project_local.hooks` (7 hooks, drifted by post-commit + pre-compact) — used by `install.sh --project-local`
- `modules.json` `dev-wiki` module `hooks` (11 hooks incl. enforcement) — registered globally by `install.sh`

A fourth axis surfaced: the enforce marker is **global** (`$HOME/.claude/enforce`), checked by all three enforce hooks. So per-project hook *registration* alone is insufficient — a scaffold would register enforce-spec yet fail-open because the marker lives in global `~/.claude`.

## Rationale

- **Root cause is multiple sources of truth.** Three lists that must agree but are edited independently produce drift; the project has three documented cascade failures of this exact class. One list with scope tags is the structural fix the handover asked for ("ONE source of truth").
- **Generate, don't hand-maintain.** `register-settings.py` already builds a settings.json from a hook list; generating the template needs no new machinery beyond scope filtering. A drift test (regenerate-to-temp, diff committed) is a deterministic validator at the boundary — Nana posture — and makes silent drift uncommittable.
- **Scope rule:** project if the hook reads/writes project state (.dev-wiki, specs, .claude/enforce, .nana, project files); global if it is session/user ergonomics independent of the project. Yields 17 project hooks + 1 global (context-size-check).
- **Marker must follow registration.** "Fully functional from py-init alone" requires the opt-in to be project-reachable, else the verification ("does it block?") can't pass without global state. OR logic (`.claude/enforce` OR `$HOME/.claude/enforce`) is backward compatible.
- **Verify firing, not presence.** The bug survived two experiment runs because reviewers checked the file existed, not that the hook fired. The exit criterion pipes a real event through enforce-spec and asserts exit 2 in a fresh scaffold.

## Alternatives considered

- **Pragmatic additive (rejected):** add the 9 enforcement hooks to `project_local.hooks`, generate the template from it, leave the global module hooks intact. Lower risk but keeps two lists with the 9 hooks duplicated — re-creating the drift this phase is meant to kill. User chose full single-source.
- **Drop the marker, enforce by default for any `.dev-wiki/` project (rejected):** simpler (kills marker-wipe failure mode) but removes the off-switch and increases gating, which the roadmap's Fix 4 explicitly warns against.
- **Bring kit self-enforcement into this phase (deferred):** committing a live `.claude/settings.json` + marker to the kit risks self-lockout mid-implementation (enforce-spec would gate edits to non-allowlisted modules.json/scripts/install.sh). The kit already enforces via existing global wiring; adoption is a deliberate later step.

## Consequences

- Fresh `install.sh` registers only global-scoped hooks (context-size-check) in `~/.claude`; project-scoped hooks come from the template (py-init) or `install.sh --project-local`. Pre-existing global enforcement registrations remain (upsert-only) — no regression for current installs.
- The generated template's structure changes from hand-grouped matchers to one entry per hook (functionally equivalent in Claude Code's nested schema).
- Enables the roadmap's verification protocol step 1 ("fresh py-init → enforce-spec registered → does it block?") to pass without global dependencies.
