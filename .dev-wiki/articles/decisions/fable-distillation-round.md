## Context

Fable-5 (removed 2026-06-13) ran signal-watch and nana-dev-kit Phases ~83-89 (Jun 9-12); the switch back to opus-4-8 produced a "drastic" felt contrast in planning, assumption-uncovering, and interaction clarity. Jake asked to distill the fable patterns and update the kit + soul so opus sessions behave more like fable. A contrastive read of paired transcripts (signal-watch fable 39-41 vs opus 15-19; kit fable 83-89 vs opus 80-82) + the external `github.com/sgup/ai` `Fable5.md` produced `eval/fable-distill/findings.md`.

Governing finding: opus already **complies with the T0 protocol and assumption gate in form, not substance** — so more prose of the same kind is the kit's own measured failure mode (Ph46 dilution, Ph47 overcorrection). The lever is context-shaping + a few *checkable* forcing-functions, not more instruction.

## Decision

Direction gate closed 2026-06-13 (A1 accept-pilot-gated, A2/A3/A4 accept; all_accept-with-A1-condition). Two tracks, both landings (global `~/.claude` + kit `templates/`):

- **Track A — codifiable lift (shipped).** Five checkable forcing-functions into `nana-soul.md`, confirmed genuinely absent first (A2 absence-diff): #1 name-likeliest-wrong-claim (folded into the uncertainty line), #2 confirmed-vs-inferred legible-from-prose (new), #3 name-what-speaks-the-old-contract (sharpened adjacent-domains), #4 no-regressions-needs-a-captured-baseline (new), #5 match-effort-to-blast-radius (sharpened cost-of-error). Net +2 lines, 3 sharpenings; parity-verified.
- **Track B1 — reframe-absorption beat (shipped).** dev-plan Step 10 now gates forward progress, when the user's answer materially reframes the approach, on restate-in-project-vocabulary + name-what-it-invalidates + check-against-loaded-constraints. Recovers fable's pause-validate (I1) structurally, not by instruction.
- **Track B2 — clean-context framing subagent (staged, pilot-gated).** Built `eval/fable-distill/framing-subagent-prompt.md` (framing generated by a subagent that never sees the proposed approach → can't validate-within-frame → recovers reframe-DEPTH / question-invalidation, I3). NOT wired into dev-plan. Deployment gated on `eval/fable-distill/pilot-protocol.md` passing in a consuming project (A1 condition — Ph80 in-kit leak + Ph47 self-dialogue-negative are the prior negatives the pilot must clear).
- **I2 mid-phase reveal-banking — deferred, not built.** Its destination (memory) is amplifier-null and is the Phase-91 prune target; building for a layer about to be cut fails the subtraction test.

Ships on judgment, not measurement (A3): interaction quality is unmeasurable in-kit (Ph59, Ph80). The B2 pilot is the one real measurement.

## Consequences

The honest ceiling is stated up front: we cannot make opus *be* fable — the biggest gaps are model-level reasoning depth/temperament; the terse-mechanical register is not chased. The bet is bounded to the checkable lines (executable, not rubber-stampable) + the two design fixes that relocate the reasoning into a context configuration where the behavior is produced not performed. Memory-layer prune bumped Phase 90 → **Phase 91** (its spec + decision article re-pointed). Phase 89 was already delivery-accepted (8e02a29); no close-out needed beyond the state-doc refresh. Trim-trial windows (d43950f/df3e623/75b48af/b8bd416) and the Phases-90-93 window-events obligation are untouched by this phase.
