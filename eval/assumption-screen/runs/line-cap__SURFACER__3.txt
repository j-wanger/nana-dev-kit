- [scope:memory-data-store] The probe checks the SAME path the MCP server actually writes to — Claude Code ignores settings.json cwd and uses the project dir, so the DB lives at <project_root>/.memory/memory.db, NOT ~/.claude/.memory/; cost-of-error: HIGHEST — probe reports 'broken'/'not-configured' against a path the server never uses, so the health line is confidently wrong AND real entries (e.g. Phase 19-48 class) silently go uncounted/irrecoverable while the line says 'healthy'.
- [scope:probe-classifier] The probe queries the correct schema — the live DB column is 'active' (not 'is_active'); cost-of-error: HIGHEST — wrong column name makes the count query error or return 0, so 'broken' fires on a healthy store (or the entry count is meaningless), defeating the entire 'accurate' success criterion.
- [scope:session-start.sh-firing] session-start.sh is actually installed and FIRING at session start in the consuming project (registered hook, not registered-but-dormant); cost-of-error: HIGH — if the hook never fires, no memory-health line is ever emitted and 'every session begins with an accurate line' is false by construction; presence != firing (a registered-but-dormant hook passes a file-presence test and ships broken).
- [scope:mcp-server-config] settings.json contains a readable `.mcpServers.memory` entry with the config shape (command/cwd) the probe parses, AND the memory MCP is actually configured for this project; cost-of-error: HIGH — if config is absent or shaped differently, probe mis-reports 'not-configured' or crashes; a bare scaffold lacking a working memory MCP would always show degraded state.
- [scope:mcp-command-venv] The MCP command / python venv the import-check invokes is present and importable; cost-of-error: HIGH — a missing venv or import failure makes the probe report 'broken' even when config+DB are fine, conflating environment setup with memory health.
- [scope:session-start.sh-budget] session-start.sh stays within its line/size budget after adding the probe + nudge — the cap (historically 70 lines, eroded to 137 across phases with no test catching it) must have a test assertion, not just documentation; cost-of-error: MEDIUM-HIGH — silent budget erosion trips Claude Code's context-size warning and degrades every session; caps need test assertions or they erode.
- [scope:probe-classifier] The three states are mutually exclusive and collectively exhaustive (config-present+db-present+importable => healthy; config-present+probe-fails => broken; config-absent => not-configured), with fail-OPEN behavior; cost-of-error: MEDIUM — overlapping/ambiguous states or a fail-CLOSED probe that hard-errors could block or mislead session start rather than warning.
- [scope:memory-nudge] The memory-nudge reminder mechanism (memory-nudge.sh) is itself wired correctly and not re-introducing the same wrong-path/wrong-column health check that the probe is meant to fix; cost-of-error: MEDIUM — a nudge that nudges based on a broken health signal is noise, and duplicating probe logic in two places invites them to drift.
- [framing] A startup memory-health status line is worth its cost at all — memory architecture classification says STRENGTHEN always-loaded `.claude/rules/` activation points rather than ADD hooks, because hooks can be unwired (3 documented cascade failures: pre-compact, MCP CWD, nana-init); a hook-based status line is the lower-durability substrate for the goal.
- [framing] An 'accurate' health line is achievable and verifiable given that the very bug class this targets (probe checking wrong path/column) produced a false 'healthy' for ~30 phases — 'accurate' must be proven by a hermetic test that pipes a real DB and asserts the count/state, not by eyeballing the line; otherwise 'success' is unfalsifiable.
- [framing] A passive status report changes agent behavior — emitting 'memory broken' at session start assumes the agent (or user) acts on it; if nothing consumes the line, it's process-theatre that adds startup lines without improving the memory outcome it's meant to protect.
- [framing] The memory-health problem is best solved by reporting state rather than by fixing the underlying CWD/path mismatch — surfacing 'broken' every session is a workaround; the higher-leverage fix may be making the server and probe agree on one canonical path so the store actually persists, making the probe mostly report 'healthy'.
