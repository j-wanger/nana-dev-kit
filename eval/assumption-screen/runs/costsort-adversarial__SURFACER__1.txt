- [scope:missing-key-default-semantics] The silent-default behavior change is the highest-cost item: today a missing key RAISES; the plan makes it return a built-in default. For any key where the old code path depended on the exception (fail-fast on misconfiguration, halting startup on a missing credential/endpoint), this converts a loud failure into a silent wrong-value. X must be true: NO caller relies on the raise-on-missing behavior as a guard — i.e. there is no security-, correctness-, or safety-critical key (auth token, DB URL, feature flag defaulting to 'on') whose absence must stop execution rather than fall back to a default.
- [scope:built-in-defaults] A complete, correct set of built-in defaults must actually exist for every key a caller can request. X must be true: every key has a defined built-in default, and that default is a SAFE value (not e.g. debug=true, ssl=false, an empty allowlist, or a placeholder) — otherwise 'missing key' silently yields an unsafe runtime config.
- [framing] The two changes are bundled but independent and asymmetric in risk: the 'minor cleanup' (raise→silent-default) is a behavior change with broad blast radius, NOT cleanup. Framing assumption: it is correct to ship this semantics change as an incidental rider on a format migration rather than as its own scoped, separately-reviewed/tested change. (Challenge: 'while we're in here' is exactly how high-cost behavior changes slip past review.)
- [scope:config.toml-parser] A TOML parser/dependency must be present and wired into the loader. X must be true: a TOML parsing library is available in the runtime/deps, imported, and the loader is actually changed to call it — the plan assumes this substrate exists but names no dependency.
- [scope:config-source-of-truth + migration] There must be a migration path from the OLD config format/location to config.toml. X must be true: existing deployments' config values are translated into config.toml (or the new loader still reads the old source); otherwise every previously-set key becomes 'missing' on cutover and — combined with the new silent-default behavior — every environment silently reverts to defaults with no error.
- [scope:config.toml-path-resolution] The loader must resolve the correct, writable, deployment-correct path to config.toml across all environments (local, CI, prod, containers). X must be true: config.toml is present and readable at the path the loader looks for in every environment; a wrong/empty path now silently yields all-defaults instead of an error.
- [framing] 'Smoother for users' assumes silent defaults are what users actually want. Challenge: for an operator, a hard error on a typo'd or omitted key is usually preferable to silently running on a default they didn't choose. Load-bearing assumption: the dominant user is one who benefits from leniency, not one who needs misconfiguration surfaced.
- [scope:type-and-validation-handling] TOML is typed (ints, floats, bools, dates, arrays, tables); the previous format may have been string-based (env/ini). X must be true: the loader and all downstream consumers handle TOML's native types correctly, and any existing value coercion/validation still runs — otherwise a value that parses fine in TOML reaches a consumer expecting a string.
- [scope:test-suite-coverage] Tests must exist that pin BOTH the load-from-toml path and the missing-key→default path, including at least one negative case proving no critical key silently defaults. X must be true: the success criteria ('configs load from toml; missing keys use built-in defaults') are actually asserted by tests, not just assumed — the stated success criteria omit any check that a required key's absence is still detectable.
- [framing] The plan defines 'missing key' as a single uniform case, but there are several: key absent entirely, key present but null/empty, malformed TOML, file absent. Load-bearing assumption: all of these should funnel to 'use built-in default' — but malformed-TOML or file-absent silently defaulting masks real deployment errors. The plan has not decided which absence modes deserve defaults vs. which deserve errors.
- [scope:callers-of-config-loader] Every call site of the config loader is a dependent of this change. X must be true: no caller does its own try/except around the loader expecting a raise, and no caller's None/sentinel handling conflicts with the new always-returns-a-value contract.
