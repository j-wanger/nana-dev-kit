- [scope:probe-failure-mode] HIGH — the probe must be fail-OPEN: if it errors (missing sqlite3, jq, unreadable config), it must degrade to an honest 'not-configured/unknown' line and exit 0, never block or crash session startup. A fail-closed probe that exits non-zero would break every session start — far worse than the absent feature.
- [scope:health-state-classification] MEDIUM — the three states (healthy / broken / not-configured) must be mutually exclusive and exhaustively cover real conditions (configured-but-empty, configured-but-unreachable, embedding-provider-down). If a real state maps to no bucket or the wrong bucket, the line is inaccurate while appearing authoritative — worse than no line.
- [scope:probe-dependencies] MEDIUM — the probe's tooling (jq for config read, sqlite3 for entry count, the MCP import check) must be present in the consuming environment; absent deps must route to 'unknown', not a false 'broken'. Assumption: every dependency the 3-layer probe relies on is available or gracefully optional.
- [scope:memory-nudge-reminder] MEDIUM — the nudge is advisory-only (a reminder), so its cost-of-error is low presence-wise, but if it duplicates existing memory-discipline nudges or fires when memory is unconfigured (nudging the agent to use a store that isn't there) it adds noise. Assumption: the nudge is suppressed/adjusted when state is not-configured.

Assumption: the installer actually copies the updated script; an un-updated template means the live consuming session never gets the probe (cascade-failure class: not-installed → silently absent).
